# PiCC deep code review — findings (2026-07-11)

Adversarial multi-agent review of the full implementation against doc/plan/picc-plan.md.
12 subsystem reviewers, every non-minor finding independently adversarially verified.
Result: **68 confirmed findings** (0 refuted), 36 unverified minors.

Status legend: [ ] open · [x] fixed (with regression test) · [~] partially addressed / registry-downgraded.

## Resolution (same day)

All 4 criticals and all confirmed majors were fixed with regression tests; minors were fixed alongside.
Five items are [~] partial by design:
- Skill allowed-tools: enforced for context:fork dispatch; in-session pre-approval is trivially satisfied under the default-permissive posture (registry: partial, safety-relevant).
- Skill model:/effort:: honored for context:fork and ${CLAUDE_EFFORT}; a non-fork skill cannot switch the parent session model (registry: partial).
- apiKeyHelper / includeCoAuthoredBy / attribution / permissions.additionalDirectories / settings.model: no consumer yet — registry downgraded to degraded-noop and the compat report now surfaces them when declared.
- Bare-tool deny: removed from subagent tool sets via gateTools; main-session Pi built-ins stay visible but every call is blocked by the guard.

## Subsystem summaries

### skills

The parsing/substitution/shell-injection core (skills.ts, shell-inject.ts) is careful and well-tested at the unit level, but the activation pipeline has a critical environment bug (shell-injection subprocesses don't inherit process.env, masked by tests that pass the full env), and several frontmatter fields the plan and the capability registry declare "full" — allowed/disallowed-tools, model, effort, paths — are parsed and then never consumed anywhere. context:fork works only half-way: it leaks the rendered body into the parent's resident context and depends on an arbitrary first-agent fallback. The §4.1 "Done when" fixture (context:fork, paths:, injection under both shells via the real pipeline) has no test.

### rules-claudemd

The CLAUDE.md subsystem (imports, hierarchy, nested lookup, comment stripping) is well built and well tested — @import hop limits, cycles, code-span/fence awareness, @~/ and absolute paths, the AGENTS.md bridge, and worktree-aware nested lookup all check out. The rules subsystem's load/parse side is solid too, but its injection side has four verified defects that all end the same way — project instructions silently not reaching the model, which the plan's floor (§2.2 "never silently misbehaves") forbids: path-scoped rule matching ignores the session cwd and worktree checkouts, subagents share (and consume) the parent session's one-shot injection state, injection state is never reset after compaction so path-scoped artifacts violate §9's "reload on next relevant access", and rule ids collide across scopes so same-named user rules are permanently suppressed. All were confirmed by executing the actual code.

### agents-subagents

The agents loader (src/claude/agents.ts) is solid: full frontmatter parse, lenient degrade, deterministic ordering, and good test coverage. The dispatch runtime (src/runtime/subagents.ts) has serious concurrency and scope-isolation defects: nested dispatches can deadlock on the shared semaphore, the orchestrator-bound Skill tool handed to subagents bypasses the depth cap and pollutes parent session state, parent/subagent share the context-injection state so directory instructions get silently dropped, and same-millisecond worktree names break isolation under parallel fan-out. Additionally, maxTurns (and color) are parsed-only while the capability registry claims them fully enforced, and the plan's isolation:worktree and depth-2-nesting "Done when" criteria have no tests.

### worktrees

The worktree core (name/path mutual exclusion, flat layout, base-ref resolution before creation, .worktreeinclude seeding, lock-on-enter, Windows-tolerant removal) is largely well built and well tested for happy paths. However, there is one catastrophic hole — ExitWorktree's unguarded rmSync fallback combined with EnterWorktree(path:) accepting the main working tree can recursively delete the entire project — plus a cluster of orphan-lifecycle defects: orphan reaping is never wired into the harness despite the tool promising it, an orphan dir is silently reused as if it were a live worktree, and a reused leftover branch records a wrong base commit. The .worktreeinclude parser also inverts gitignore-style negation lines into match-everything patterns.

### hooks

The hooks subsystem is well-structured and genuinely crash-hardened (parse-and-degrade holds up under garbage input, timeouts, missing bash, bad JSON), and the stdin/stdout contract core (exit-2, permissionDecision, additionalContext, updatedInput, disableAllHooks) is implemented and tested. However, there are two behavioral divergences from Claude Code semantics (unanchored matcher regex; matcher unusable on SessionStart/PreCompact source matching), and several places where a computed HookOutcome is silently discarded by callers (PostToolUse block feedback, SubagentStop blocks, all diagnostics and ask-downgrades), which undermines the plan's "deterministic enforcement layer" claim. Skill re-activation also leaks duplicate scoped hook runners.

### permissions

The core engine is well-structured, never-throwing, and well unit-tested for the paths it implements (Bash chaining polarity, domain rules, MCP prefixes, gateTools). However, measured against the plan's own bar — "deny honored as a hard, non-interactive block" plus "permission-matcher grammar fully implemented" as defined by doc/research/02 §7 — there are real deny-bypass holes: Edit rules do not cover Write/NotebookEdit, path-rule anchoring drifts with the session cwd (worktree entry breaks it), and Claude's documented wrapper-stripping and parameter-matching forms are absent and unreported. Runtime ask-downgrade reporting is dead code. None of these are caught by the current tests.

### discovery-settings

The settings loader's precedence/merge/JSONC core is solid and well tested at the parse level, but the subsystem fails plan §5's actual bar: six settings (skillOverrides, apiKeyHelper, cleanupPeriodDays, includeCoAuthoredBy, attribution, permissions.additionalDirectories) are parsed and then consumed by nothing, while the capability registry marks all six "full" — so the compat report (§6.2/§17) actively lies about them. I also verified two never-crash-floor violations end-to-end: a hooks block with a "__proto__" event key makes loadSettings throw (aborting the whole extension load), and a UTF-8-BOM settings.json (Windows Notepad default) is skipped entirely, silently dropping deny rules. Tests assert parsing, not behavior, which is exactly why the unhonored-toggle gap shipped unnoticed.

### plugins

The core of the b393e6e fix is correct: resolveEnabled defaults to disabled, marketplace catalogs stay dormant, and project.ts filters to enabled plugins before folding content. However, I found one confirmed never-crash-floor violation (malformed blocklist.json throws out of discoverInstalledPlugins, which at startup disables the whole harness), a real enable-state precedence bug (enabledPlugins is replaced wholesale per settings file instead of key-merged, so a project settings file silently disables all user-enabled plugins), and a divergence from the repo's own research doc: plugin skills/agents are folded under bare names with no `plugin-name:` namespacing, so CC-style invocations fail and collisions silently drop plugin content. The exact regression b393e6e fixed has no assembly-level test guarding it.

### tool-surface

The tool-name mapping, permission-matcher reuse, and degrade stubs are solid and honor the never-crash floor; tests cover the JS grep engine, web tools, task tools, and stub callability well. However, the Claude-named tool instances are created once, bound to main-session state, and handed verbatim to every subagent — leaking the TaskStore and the main-session cwd into worktree-isolated subagents. The Grep tool's two engines (ripgrep vs JS walker) search materially different file sets and produce different output shapes for single-file targets, and the entire ripgrep path is untested. Grep's parameter surface is a visible subset of the Claude Code baseline that skills rely on.

### registry-compat

The compat-report machinery (scan, grouping, notice/doctor rendering, suppression persistence) is structurally sound and well-tested at the unit level, but the subsystem fails its own two core promises. First, buildCompatReport crashes at extension startup (unprotected call in index.ts) on a skill hooks: frontmatter shape that PiCC's own hook parser accepts — a hard violation of the never-crash floor, reproduced end-to-end. Second, the "no drift" guarantee is inverted: the registry itself overstates support, claiming "full" for at least 13 settings/frontmatter fields that are parsed but never consumed anywhere (settings.model, includeCoAuthoredBy, attribution, apiKeyHelper, cleanupPeriodDays, skillOverrides; skill allowed-tools/disallowed-tools/model/effort/paths; agent permissionMode/maxTurns/color), so /doctor — generated from the registry — actively tells users these work when they are silent no-ops, which is exactly the "silently deprived" failure §6.2 exists to prevent. The scan also produces false "unassessed" noise for fully-supported specifier tool entries and for degrade-stub tools PiCC actually ships.

### extension-wiring

The extension wiring is largely faithful to the Pi ExtensionAPI (event names, return contracts, registerCommand vs input double-execution, entry renderers, and steer-mode context injection are all correct), and the previously known /doctor deliverAs bug is fixed and regression-guarded. However, the same wrong-deliverAs class recurs in the compaction-preservation path, session context state is shared between the orchestrator and all subagents (consuming once-per-session injections cross-scope), repeated skill activation stacks duplicate scoped hook runners, and post-compaction reload of nested CLAUDE.md/path rules promised by plan §9 is not implemented. Several wired lifecycle handlers (after_provider_response quota capture, model_select steering, agent_settled Stop loop, SessionEnd) have zero test coverage.

### util-crossplatform

The never-crash floor is well-honored (safe wrappers everywhere), but the shared glob engine — explicitly cross-cutting per plan §4.2 (permission rules, path-scoped rules/skills, claudeMdExcludes, .worktreeinclude) — has several empirically confirmed correctness holes, one of them security-relevant (permission deny rules silently stop matching when the project path contains glob metacharacters like parentheses, common on Windows). The lenient frontmatter fallback silently destroys zero-indent YAML lists (a very common Claude agent shape), walkFiles never traverses junctions/symlinked directories on any platform, and a UTF-8 BOM (PowerShell 5.1 default) causes whole settings.json files to be dropped. The glob engine itself has no direct unit tests, so none of these would be caught.

### agents-subagents

- [x] **MAJOR / bug** — Nested subagent dispatch can deadlock on the shared concurrency semaphore
  - Where: `src/runtime/subagents.ts:173`
  - A parent dispatch holds its semaphore slot for the entire session.prompt() (subagents.ts:173 acquire, released only in finally). A nested Agent tool call inside that prompt dispatches through the SAME SubagentRuntime/Semaphore and must acquire another slot. With subagentConcurrency=N (settings default 4, user-settable to 1), any state where N ancestor dispatches hold slots while each awaits a queued descendant deadlocks forever: with concurrency 1, EVERY depth-2 nesting (or any context:fork skill invoked from inside a subagent) hangs the session; with the default 4, a 4-wide fan-out where each agent nests once hangs. The plan requires both a depth-2 nesting fixture and a configurable concurrency cap (§4.3, §12.2) — they are mutually broken. The semaphore has no timeout, so this is an unrecoverable hang, violating the never-wedge floor (§2.2).
  - Fix: Only count leaf/root-level dispatches against the semaphore (e.g., release the slot while awaiting session.prompt and reacquire around result extraction), or scope the semaphore per depth level, or acquire with a depth-aware bypass for nested dispatches so ancestors never starve descendants.

- [x] **MAJOR / bug** — Parallel fan-out of a worktree-isolated agent can silently share one worktree (Date.now name collision)
  - Where: `src/runtime/subagents.ts:186`
