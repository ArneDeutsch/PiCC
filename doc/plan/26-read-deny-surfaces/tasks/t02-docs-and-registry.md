## Context & seams

- **`doc/user-guide.md` §6 "Security & permission posture" (~line 365) — the primary,
  required home.** It enumerates the deny matcher grammar for maintainers:
  `Read/Edit(glob)` … — currently presenting `Read(glob)` as protecting only `Read`.
  This is the durable, discoverable place a maintainer configuring a deny will look, so
  it is where the read-family behavior AND the honesty caveat must land. Update the
  grammar bullet to state `Read(glob)` also gates Grep/Glob/NotebookRead on a matching
  path (NotebookRead noted as inferred defense-in-depth), and add the caveat adjacent to
  it (see "honesty caveat" below).
- **`doc/architecture.md` (~line 168) — contributor altitude.** It already documents the
  edit-family analog this feature mirrors ("an `Edit(…)` rule already gates the file-edit
  family"; `Write` doesn't gate `Edit`). Add a parallel sentence for the read-family
  (`Read → Grep/Glob/NotebookRead`, one-directional) so the permission-engine description
  doesn't leave an undocumented asymmetry between the two families.
- **CHANGELOG.md** — add an entry under `[Unreleased]` following the repo's actual
  Keep-a-Changelog convention: a categorized heading `### <Category> — <title> (YYYY-MM-DD)`
  (match a heading form still present in `[Unreleased]`; do not assume F17/F18 are still
  there). F26 closes a parity/security divergence in existing behavior, so use
  `### Changed` (or `### Fixed`, framed as closing the gap) — NOT `### Added`. One or two
  lines: a `Read(<glob>)` deny now also gates Grep/Glob/NotebookRead on matching paths,
  mirroring Claude's best-effort read-rule coverage.
- **doc/supported-features.md** (generated from the registry) — the `setting.permissions.deny`
  capability in `src/registry/capability-registry.ts` (~line 145) is tagged `full`
  ("hard, non-interactive block — the kept deterministic safety valve (§6.1)"). Decide
  with the docs reviewer whether that entry should gain a short clause noting the
  read-family coverage. **If and only if** you change registry source text, run
  `npm run gen:capabilities` and commit the regenerated matrix. The authoritative
  consistency guard is the vitest freshness test `test/registry.test.ts` ("capability
  matrix freshness"), which re-renders the matrix in-process and asserts it equals the
  committed `doc/supported-features.md` — so if registry text is unchanged, do NOT run a
  spurious regeneration (a no-op regen is byte-identical and the test passes either way).
- **The honesty caveat (required, in `doc/user-guide.md` §6).** State the limit plainly.
  **Pinned behavior from t01 (use these exact facts — an earlier assumption was wrong):**
  matching is on the tool's path argument. `deny: Read(secrets/**)` DOES block a
  Grep/Glob/NotebookRead call whose `path` names the protected directory *or* a subpath
  (`{path:"secrets"}` and `{path:"secrets/x"}` are both blocked — the glob engine covers
  the bare directory node). The genuine residual gap is a read call with **no path** or
  `path: "."`: `Grep {}` / `Grep {path:"."}` are NOT blocked, because there is no path to
  match, yet their results can surface matching file contents. Only a **bare**
  `deny: Read` (which removes the read tools from context entirely) fully forecloses that
  content-exfil path. This is inherent to path-glob matching (not new in F26) and is
  Claude Code's own best-effort limitation — state it, don't oversell containment.
  CHANGELOG/registry are fine secondary homes, but the caveat MUST appear in
  user-guide §6; CHANGELOG alone is insufficient (it scrolls into release history, away
  from where denies are configured). Do NOT repeat the earlier draft's incorrect
  "naming the bare directory may not match" wording — the bare directory IS matched.
- **Fixture — intentionally not grown.** `examples/full-surface/.claude/settings.json`
  already ships `deny: ["Read(secrets/**)"]`, and `test/e2e-live-pi.test.ts` already
  drives it end-to-end. Per the tester's guidance the guard→engine path is generic once
  `ruleToolMatches` expands, so a parallel Grep/Glob e2e fixture would be dead weight;
  the unit tests in t01 fully prove the contract. Record this decision (one line) in the
  log so the un-grown fixture is a conscious choice, not an oversight.
