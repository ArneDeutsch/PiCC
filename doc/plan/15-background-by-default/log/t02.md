# t02 execution log — Bound nested (depth ≥ 2) background fan-out (per-depth budgets)

## Per-depth structure chosen — and why
- Kept the existing root `Semaphore` for `depth ≤ 1` unchanged (its role IS "depth-1
  budget"), and added a lazy `Map<number, Semaphore>` (`nestedBudgets`) that mints one
  `Semaphore(Math.max(1, concurrency))` per nested depth on first use
  (`budgetForDepth(depth)` in `src/runtime/subagents.ts`).
- Rationale for per-depth (NOT a single shared / single dedicated nested pool): a
  dispatch holds its slot for the whole session, and a slot-holder can block in
  `TaskOutput(wait)` on its own background child (session-wide registry). If a
  descendant acquired the SAME pool an ancestor holds, `C` ancestors each awaiting a
  queued child deadlock (guaranteed at `C = 1`, any single depth-2 nesting). With one
  budget per depth, an ancestor at depth `d` holds a slot in pool `d` while the
  descendant waits in pool `d+1` — never the same slot → no cross-depth wait-for cycle
  → deadlock-free even at `concurrency = 1`. Total nested concurrency is bounded by
  `maxDepth × concurrency`, both finite and config-capped (`subagentMaxDepth`,
  `subagentConcurrency`); no new user-facing knob.
- All depths share the SAME numeric budget (`concurrency`), not a scaled one. Simplest
  finite bound; scaling would only tighten/loosen a number that is already conservative.

## Acquire gate (~782)
- New predicate: `const foregroundNested = opts.depth > 1 && !opts.background;`
  - foreground nested (`depth > 1`, no `background`) → keeps its `() => {}` bypass
    (its deadlock argument — a foreground parent blocks holding its slot while awaiting
    a synchronous child — is the reason the bypass exists; unchanged).
  - everything else (`depth ≤ 1`, OR background `depth > 1`) → acquires
    `budgetForDepth(opts.depth)`. For `depth ≤ 1` that IS the old root semaphore, so
    root behaviour/tests are byte-for-byte unchanged.

## `background` flag threading
- Added optional `background?: boolean` to `dispatch()`'s opts (documented; ignored at
  `depth ≤ 1` since root always acquires its own pool).
- Set `background: true` on the tool handler's background arm (`createAgentToolDefinition`,
  the un-awaited `runtime.dispatch(...)` inside `registry.start`).
- Set `background: true` on the `SendMessage`-resume dispatch (un-awaited via
  `backgroundTasks.start`, dispatched at `record.depth`).
- Foreground arm (awaited) and `forkDispatch` (`src/index.ts`, awaited) left `background`
  UNSET — they keep the foreground bypass.

## SendMessage-resume depth rationale (required, not optional)
- `SendMessage` is parent-initiated only, so the COMMON resumable agent is depth-1 —
  which acquires its root pool regardless of the flag, so the flag is a no-op there.
- The NARROW-but-real case: a grandchild id that bubbled up to the root is resumable at
  `record.depth ≥ 2`. Without `background: true` it would hit `depth > 1 && !background`
  → the foreground bypass → an UNBOUNDED escape from the nested bound. Setting the flag
  routes it through the per-depth budget. Deadlock-free: the only waiter on a resume is
  the root, which holds no slot.

## Bounded-wait property (for t03 docs)
- The only awaiting edges are foreground-parent → foreground-child, and foreground
  children never acquire a slot, so a queued background child is never awaited by a
  slot-holder in its own pool → no starvation cycle. But a nested background child may
  still wait for an ancestor turn to release before it starts: deep fan-out is
  bounded-wait, NOT unbounded-immediate parallelism at every depth. "Background fan-out"
  must not be read as infinite parallelism.

## Divergence from Claude (hand-off to t03 docs)
- Claude's parallel-agent cap is a GLOBAL ~10. Per-depth budgets instead allow up to
  `maxDepth × concurrency` total across the tree. This is a conservative PiCC safety
  choice (bounded, finite, deadlock-free), documented as such — not claimed as exact
  Claude parity.

  `SubagentStart`; without the flag `foregroundNested = depth > 1 && !background` is true →
