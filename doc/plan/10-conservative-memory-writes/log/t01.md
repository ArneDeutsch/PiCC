## Key decisions
- **Final `MEMORY_WRITE_POLICY` prose** (used the recommended draft verbatim; it satisfies
  every assertion): "Unless this project's own instructions tell you to record memory
  proactively, do not write to memory on your own initiative — routine facts you pick up
  while working do not belong here, and low-value entries only crowd out what matters. Add
  or update an entry only when you are explicitly asked to remember something for the future
  (for example \"remember to…\", \"from now on…\", \"in future don't…\", or \"make a note
  that…\"). When you do, use the Write/Edit tools with one topic per file and MEMORY.md as
  the index (only MEMORY.md is loaded automatically — keep it under ~200 lines). Remove or
  correct an entry only when you are told it is wrong or obsolete."
- **Deference clause**: the policy opens with "Unless this project's own instructions tell
  you to record memory proactively, …" so a CLAUDE.md eager-write opt-in (emitted earlier in
  the prompt) wins. Asserted deterministically in memory.test.ts via
  `toMatch(/unless[^.]*instructions/i)`.
- **Per-agent unique-phrase assertion**: replaced the old `toContain("MEMORY.md as the
  index")` (which the co-injected `# Auto memory` section also satisfies) with
  `not.toContain("You may persist")` — a phrase unique to the old per-agent string, so it
  proves the per-agent flip specifically rather than being a false green.
- Kept the framing lead-ins as plain string literals (agent one inlined at the call site,
  project one as a module const) matching the surrounding idiom.
- Word "proactively" appears only inside the deference clause (allowed by the spec — the
  negative `not.toMatch(/proactively/i)` guard was intentionally dropped on auto-memory
  `out`). "whenever you learn" is fully removed; regression-guarded.
