## Review-finding application (2026-07-15)

Applied the five accepted review findings.

- **SHOULD-1 (broaden `gh api` deny matchers).** Added 10 matchers to `.claude/settings.json`
  `permissions.deny` (kept all 20 existing): leading-flag forms `Bash(gh api -X *)`,
  `Bash(gh api --method *)`, `Bash(gh api -f *)`, `Bash(gh api -F *)`, and long-form field flags
  `Bash(gh api --field *)`, `Bash(gh api --raw-field *)`, `Bash(gh api --input *)`,
  `Bash(gh api * --field *)`, `Bash(gh api * --raw-field *)`, `Bash(gh api * --input *)`. Verified
  against the matcher grammar in `src/engine/permissions.ts`: Bash rules compile with
  `trailingSpaceStar` (a trailing ` *` = "space or end"), so a leading-flag matcher requires the literal
  flag immediately after `gh api `, and a `* --field *` matcher requires a literal ` --field` somewhere.
  The GET read `gh api repos/<t>/issues/<N> --jq '...'` carries none of those flags, so it stays NOT
  denied — confirmed both by reasoning and a new behavioral test.
- **SHOULD-1 (soften overclaiming).** Reworded SKILL.md's fixed-action-envelope paragraph and
  write-discipline.md's allow-list note: the floor now honestly denies the *common* `gh api` write
  forms, with the explicit caveat that a `*`-anywhere matcher cannot express "flag in any position", so
  it is defence-in-depth; the real controls named are the shell-free `evaluator` sandbox (structural) +
  the trusted-coordinator envelope discipline + close-invariant.
- **SHOULD-2 (negative-control deny tests).** Added PermissionEngine assertions in
  test/evaluate-skill.test.ts that the four newly-covered forms ARE denied
  (`gh api -X PUT repos/o/r/pulls/5/merge`, `gh api --method PATCH repos/o/r/issues/5`,
  `gh api repos/o/r/labels --field name=bug`, `gh api repos/o/r/issues/5 --raw-field body=x`) and that
  the GET `gh api repos/o/r/issues/5 --jq '.state'` is still NOT denied. Also extended the matcher-pin
  `expected` list with the 10 new matchers.
- **Parity SHOULD (behavioral vs structural relabel).** In SKILL.md and evaluation-engine.md, split the
  redirect isolation into two halves: the `evaluator`'s inability to write/fetch/run is STRUCTURAL
  (tool-gated); the coordinator's non-ingestion is a DISCIPLINED REDIRECT (behavioral) resting on the
  unverified `gh … > <file>` ⇒ empty-stdout premise (pending one live smoke test). Removed the claim
  that the coordinator half is tool-enforced / an equal structural guarantee.
- **Test polish (coder + tester).** (a) Relaxed the exact-two-references `toEqual([...])` to a superset
  check (the bidirectional glob integrity already guards completeness), so t02–t04 needn't edit it.
  (b) Added `expect(skill!.diagnostics).toEqual([])` — per-skill parse diagnostics are on the skill,
  not in the top-level `loadSkills` array (verified in src/claude/skills.ts), so this closed a real gap.
  (c) Added `expect(skill!.userInvocable).toBe(true)`.
