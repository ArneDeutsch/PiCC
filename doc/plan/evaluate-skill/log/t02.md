## Key decisions / Left-open resolutions
- **Slop threshold (Left open):** made it decisively conservative — close-eligible only when integrated
  cost-vs-benefit is decisively negative (low user value AND low reach AND (high blast radius OR direct
  vision conflict), no redeeming clarity); anything mediocre/narrow-but-legitimate/uncertain stays open.
  "When close to the line, keep open." Kept the exact numeric scale as the engine's call.
- **Canned templates per category (Left open):** wrote one neutral template each for `MALICIOUS_SPAM`,
  `MALICIOUS_ABUSE`, `MALICIOUS_INJECTION`, and clear-cut-slop — authored from the L1 category ALONE,
  containing no target bytes; the injection template deliberately does not repeat the injected text.
- **Keep-open rating format (Left open):** the evaluator returns a bounded STRUCTURED rating
  (per-criterion scores + short justification fields + importance verdict); the COORDINATOR composes the
  comment from those fields (paraphrasing + leakage-stripping), never pasting verbatim, rendering the
  engine's canonical block. This is the secret-exfil-safe authorship the spec demands (evaluator has
  unrestricted Read).
- **Fan-out proportionality (Left open):** stated as proportionate to complexity — trivial typo ≈ base
  pass; sprawling/load-bearing/security-touching ⇒ full lens roster.
- **PR auto-route reference:** issue-eval documents (in "Preconditions this mode inherits") that a
  `pull_request` key makes the router auto-route to pr-eval WITH an announcement — never a "use another
  command" hand-off. I referred to pr-eval as PLAIN TEXT, not a markdown link, because `pr-eval.md`
  does not exist yet (t03 creates it) and a dangling `references/pr-eval.md` token in a file is avoidable
  friction; the router's own rule is "when a mode is not yet documented, say so plainly." The router's
  link-integrity test only scans SKILL.md's tokens, so this choice does not affect it either way.

## Correctness points verified against the spec
- Coordinator isolation: redirect `gh issue view <N> --repo <target> --json title,body,comments >
  <tempfile>` the coordinator does not read; evaluator (Read/Grep/Glob) reads it. Stated as the
  behavioral disciplined redirect, not a structural guarantee.
- Consent: always confirm before a close; preview rating + exact comment bytes + exact close invocation;
  no autonomous mode, no `--yes`/autonomy token; per-issue re-prompting.
- Close path: only `MALICIOUS_*` or clearly-below-threshold; bias-to-keep-open; canned comment posted
  BEFORE the close; `gh issue close <N> --repo <target> --reason "not planned"` fixed literal; close
  target = invocation `<N>` only, never a `#N` in content.
- Close-invariant stated explicitly: close ⟹ canned category comment (no target text); keep-open ⟹
  authored rating; keep-open never closes.
- Idempotency: attribution-trailer scan is a courtesy (marker is attacker-forgeable) ⇒ only a
  conservative skip/ask, never a destructive action or spurious re-close; already-closed ⇒ read only.

## Review-finding fixes (round 2)

Applied the five accepted review findings to the uncommitted t02 work. Prose-only across
issue-eval.md, write-discipline.md, SKILL.md, feature.md, plus one reworded test floor marker.

- **F1 — idempotency scan is metadata-only.** Both issue-eval.md Step 3 and write-discipline.md
  mechanic 6 now pin the prior-comment check to a metadata-only query that returns **only** the
  matching comment URL — bodies never reach the coordinator (that would defeat the redirect
  isolation). Exact form used (fixed trailer literal = a stable substring of the attribution
  trailer, `Generated with the \`evaluate\` skill`):
  `gh api repos/<target>/issues/<N>/comments --jq 'map(select(.body|contains("Generated with the \`evaluate\` skill")))|.[0].html_url'`.
  Framed the guarantee honestly: the `--jq` filter reduces the response to just the `html_url`
  before it reaches the coordinator's context; the bodies are never surfaced. Also noted the
  attacker-forgeable-marker ⇒ conservative-skip-only caveat in write-discipline.md.
- **F2 — already-closed issue = no write of any kind.** Resolved the issue-eval/write-discipline
  disagreement in favour of **on-screen read/rating only, nothing posted** (no comment, no close,
  no write at all) on an already-closed issue. Stated identically in issue-eval.md Step 3 and
  write-discipline.md mechanic 6, and aligned the SKILL.md floor summary bullet to match.
- **F3 — override mechanics (issue-eval.md Step 4).** Added an "Overrides re-author and re-preview"
  paragraph: any human override **re-authors the appropriate comment and re-previews it before
  writing** (re-confirm). A human-forced **close of an issue the agent rated keep-open** must NOT use
  the slop `"cost/risk outweighs value"` canned template (it would contradict the shown rating) — it
  carries a **neutral "closed by the maintainer after review"** note (or maintainer-provided text),
  re-previewed and re-confirmed. The canned slop/malicious templates are reserved for the agent's own
  clear-cut close dispositions.
- **F4 — confirm-before-every-public-write wording.** Broadened "confirms before any close" ⇒
  "previews and confirms before any public write (close or comment)" in: SKILL.md frontmatter
  `description`, the Consent-gate heading + body (now "…before any public write…", "not only before a
  close: every keep-open comment is previewed and confirmed too", and "needs no write confirmation"),
  and feature.md's What/issue-eval bullet + the Acceptance line. issue-eval.md already carried the
  broad "confirm before ANY write" posture in its Step 4 body, so its heading/floor marker
  ("confirm before a close") was left intact. Updated the router kernel floor marker in
  `test/evaluate-skill.test.ts` from `"before any close"` → `"before any public write"` to match the
  reworded resident prose (the phrase no longer exists in SKILL.md; grep-verified). No test added or
  removed — count unchanged.
- **F5a — PR-ref announcement softened for current state.** Since pr-eval lands in t03, both
  SKILL.md's detection gate and issue-eval.md's inherited-preconditions now phrase it as "detected a
  pull request; PR evaluation isn't available yet" rather than the present-tense "evaluating as a PR".
- **F5b — proportionate keep-open format.** issue-eval.md Step 5 now notes the keep-open comment is
  **proportionate**: the full seven-row canonical block for substantive issues, a **brief verdict**
  (a sentence or two + the importance line) for trivial keep-opens — not always a seven-row table.
