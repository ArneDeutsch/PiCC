## proposal-gate.md contents
- **Structural zero-writes invariant** stated up front and tied to the mechanism: runs as the
  shell-free `evaluator` sandbox agent (`tools: Read, Grep, Glob`) — physically cannot write/fetch/fan
  out. No `<N>`/target (proposal not-yet-filed). `gh issue close` is **never** part of this mode;
  neither is any comment or `gh issue create` (the create, when it happens, is implement-feature's own
  consented write).
- **Lightweight path:** a **single** `evaluator` dispatch, not the full committee (fork-under-fork per
  candidate is expensive + risks the background-pool deadlock). A genuinely borderline candidate may
  earn a **second `evaluator` pass** (lean roaster/pro-con framing) — **never** a Bash-capable
  `generalist`, so the mode stays structurally shell-free end to end.
- **Bounded structured return + coordinator-composes:** evaluator returns per-criterion scores + short
  bounded justifications + an overall importance verdict (not free prose); coordinator leakage-strips
  and applies no-verbatim-reflection before embedding into any body (evaluator has unrestricted Read).
- **Canonical rating block** rendered (seven criteria rows + overall-importance line carrying the
  disposition), proportionate depth. When filed, embedded under a **clearly-delimited `## Evaluation`
  heading** so implement-feature's Phase 3 resume re-read of the synthesized cached `body` does not
  ingest the rating as feature scope.
- **Dispositions:** drop (gate, clear slop only, conservative) / surface (gate, borderline+) /
  annotate (Phase 1, never a close, never suppresses).
- **Wiring section** documents both implement-feature call sites (gate force vs. annotate force).

## implement-feature wiring — insertion points + reconciliation

  slop, never adds — the invariant 'never file anything not surfaced by this build' still holds."
  **Reconciliation:** rewrote the trailing "choose per finding / never file wholesale" into ONE
  coherent rule — "the gate silently drops only clear slop, and you choose per _surfaced_ finding —
  never file the surfaced list wholesale, each borderline-or-better finding is its own per-item
  decision." No other prose in that hook was disturbed; the `--body-file`/allow-list/Rule-5 mechanics
  that follow are untouched.
- **Phase 1 annotate** — `references/ticket-creation.md`, in "## The offer", appended to the body
  bullet ("The body is the converged WHAT/WHY … ending with the `<attribution trailer>`"). Inserted:
  "Annotate that body with evaluate's proposal-gate … embeds that assessment under a clearly-delimited
  `## Evaluation` heading, kept visibly separate from the WHAT/WHY so the Phase 3 resume re-read of the
  synthesized cached `body` (the FILE step below) never ingests the rating as feature scope. Here
  proposal-gate only annotates — it never suppresses this offer … even a low score is surfaced (the
  human may still file, edit, or decline it in this preview), never a silently-vanished offer." The
  Phase 3 FILE step and its synthesize-cached-JSON step were left as-is (the delimited heading is the

## Left-open decisions
- **Surface/annotate threshold, borderline-vs-slop:** reused issue-eval's conservative slop-threshold
  shape — clear slop = decisively-negative integrated cost-vs-benefit (low value AND low reach AND
  (high blast radius OR direct vision conflict), no redeeming clarity); everything else is
  borderline-or-above and surfaces. Close to the line ⇒ treat as borderline, not slop.
- **Assessment-block layout:** the engine's canonical rating block (seven rows + overall-importance),
  consistent with t02/t03; disposition is drop/surface/annotate, never close.
- **Borderline extra pass:** a genuinely borderline candidate may earn a second `evaluator` pass (lean
  roaster/pro-con) — never a `generalist` — so the shell-free guarantee holds; clear-cut proposals need
  only the single sandbox score.

## Review-finding revisions (t04, second pass — accepted findings applied)

Applied five accepted review findings to the uncommitted t04 work. Net effect: the Phase 1 value
assessment is now an **in-session advisory** the human sees in the create-offer exchange, and is no
longer embedded into the filed public issue body; the `## Evaluation` body-embed now applies **only**
to Phase 8 filed findings.

- **Finding 1 (BIG ONE) — Phase 1 → in-session, not body-embedded.**
  - `proposal-gate.md`: replaced the old "when a proposal is filed, embed under `## Evaluation`"
    paragraph (which conflated Phase 1 and Phase 8) with a two-bullet "where the assessment lands"
    block. Phase 1 (annotate) = presented **in-session** in the offer exchange, filed body stays
    WHAT/WHY only. Phase 8 (gate) filed findings = the `## Evaluation` body-embed, kept there
    intentionally (a filed finding is a standalone issue, never re-read as current-feature scope). The
    disposition-list `annotate` bullet and the Wiring Phase 1 bullet were reworded to in-session too.
  - `ticket-creation.md`: the offer body bullet no longer says "embed the assessment under
    `## Evaluation`". It now runs proposal-gate over the converged scope and **presents the assessment
    in-session as part of the offer exchange** ("before I file, my read on the value is …; still want it
    filed as written?"); the filed body is WHAT/WHY only. The Phase 3 FILE step's synthesized cache
    `body=<the WHAT/WHY just filed>` was already correct and left **unchanged**.
  - `implement-feature/SKILL.md`: Phase 1 router note changed from "the offered body is annotated
    (never gated)" to "the offer carries an **in-session value advisory** … not baked into the filed
    body". The evaluate SKILL.md router note did not imply a Phase-1 body-embed, so it was left
    untouched (also keeps it under the 20k cap — unchanged at 12,011 chars).
- **Finding 2 (generalist SHOULD-3) — "surfaced" → "presented".** In `ticket-integration.md`'s Phase 8
  hook, the two post-gate pick usages became "presented" ("borderline and above is **presented** with
  its assessment embedded"; "you choose per _presented_ finding — never file the presented list
  wholesale"). The origin-sense invariant "never file anything not surfaced by this build" keeps sole
  ownership of "surfaced".
- **Finding 3 (UX SHOULD-2) — recover-dropped in-flow lever.** Both `ticket-integration.md` and
  `proposal-gate.md` now state the tally is an in-flow lever, not just a pointer: the maintainer can
  **ask to see the gate-dropped findings and the coordinator surfaces them into the pick-list on
  request** (they remain in `review.md` as the durable record).
- **Finding 4 (UX SHOULD-3) — Phase 8 embed location.** `proposal-gate.md` now states explicitly that a
  surfaced Phase 8 finding's assessment appears **both** in the in-session pick presentation **and**, if
  the user files it, embedded under `## Evaluation` in that finding's filed body.
- **Finding 5 (UX NIT) — surfaced findings stay substantive.** `proposal-gate.md` now scopes the
  "proportionate / brief-verdict" allowance to **trivial keep-opens only** (issue-eval's territory);
  every surfaced (borderline-or-above) proposal-gate finding always carries the fuller rating, never a
  one-line stamp.
