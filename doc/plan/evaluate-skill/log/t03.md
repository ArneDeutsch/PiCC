## Key decisions ("Left open" items)
- **Assessment-comment layout / merge-readiness heuristic:** rendered as the engine's canonical
  rating block with three PR-specific rows added (Fulfilment / Code consequences / Verification
  evidence) plus the overall-importance line carrying an advisory `ready | needs-work | hold`

  second layout.
- **Verification-request copy:** kept it as a described contract (helpful, one-time, points at
  CONTRIBUTING + PR template, never a close threat) rather than pinning exact bytes, so t05 can
  author the contributor-facing copy consistently. Named the canonical evidence noun exactly:
  **"manual-verification comment"**.
- **Diff investigation depth:** proportionate to size/risk — base pass for a docs one-liner, full
  roaster/pro/con + security + blast-radius/coder lenses reading line-by-line for a load-bearing
  change.
- **State short-circuit:** on closed/merged (`state == closed` or `mergedAt` non-null) the advisory
  readiness line is dropped/reframed as retrospective, no verification-request fires, and only a
  read is offered (a neutral retrospective comment only on explicit consent).

## How pr-eval.md threads with handoff.md
The applicability rule is stated on its own merits and explicitly cross-links
`../../implement-feature/references/handoff.md`. It adopts handoff.md's existing doctrine that a
skill/harness/prose change has a runtime surface — **picc executing the changed behaviour** — and is
therefore NOT exempt from manual verification; only genuinely no-runtime-surface (docs) or
fully-and-genuinely automated-test-covered changes are exempt. It does NOT cite a `/verify` skill
(that is a Claude Code bundled skill absent from this repo), per the spec.

## Redirect / isolation parity with issue-eval
Coordinator resolves metadata only (requires the `pull_request` key) and redirects the diff + PR
JSON to OS-temp files it does not Read (`gh pr diff > <difffile>`,
`gh pr view --json ... > <metafile>`); every reviewer (L1 screen, roaster, pro/con, lenses) is a
shell-free `evaluator` dispatch pointed at those files, which cannot run the author's reproducer,
fetch a link, or write. Idempotency scan is metadata-only via the same `--jq html_url` filter and
carries the attacker-forgeable-marker caveat (conservative skip/ask only). Assessment authorship is
secret-exfil-safe: evaluator returns a bounded structured assessment, coordinator composes the
comment (never verbatim), leakage-stripped, via `--body-file`, confirmed before posting.
