## Key decisions

- **Shared closure (`runSkillActivation`).** Extracted the post-resolution body of
  `createSkillTool.execute` verbatim into a session-scope `async function`
  (hoisted, so it's usable both by `createSkillTool` and `createSlashCommandTool`,
  which sit before the customToolsFor grant site at line ~621). Signature exactly
  as the spec: `(skill, argsText, { forSubagent, depth, invokedName })`.
- **Behavior-preservation trap honored.** The `disable-model-invocation` refusal
  message is built from `opts.invokedName` (the caller-supplied name), not
  `skill.name`. The Skill tool passes `params.name`, SlashCommand passes the parsed
  `<name>` — so the Skill tool's existing wording/tests are unchanged. Confirmed:
  Skill tool's `refuses model invocation of user-only skills` test still green.
- **Gate on disable-model-invocation ONLY.** No `userInvocable` check added —
  `/rust-helper` (userInvocable:false) runs, `/secret-ritual`
  (disable-model-invocation) is refused. Locked in by tests.
- **Parse helper extracted** (Left-open decision): a module-level pure
  `parseSlashCommand(command)` returning `{name, argsText} | undefined`. Regex
  `^\/?([A-Za-z0-9][\w-]*(?::[\w-]+)*)(?=[ \t]|$)` mirrors the transform's token
  shape (optional leading slash, plugin `:` namespacing, `[ \t]` separator). Single
  command, no stacking. Empty/whitespace/bare-`/` → undefined → the dedicated
  `SlashCommand requires a command like "/name args".` throw.
- **Tool `description`** (Left open): kept short — states the `/name [args]` format,
  points at the same "Available skills" listing the Skill tool cites, and notes
  equivalence to the Skill tool for `/name args` strings.
- **CHANGELOG** (Left open): added `### Added — SlashCommand tool (2026-07-14)`
  under `[Unreleased]`, mirroring the registry-truthfulness entry style; names the
  new `partial` tier and the registry-regenerated matrix.
- **Breadcrumb comment** (Left open): yes — replaced the removed `DEGRADED_TOOLS`
  block with a one-line "SlashCommand is a REAL tool now (F11)" breadcrumb next to
  the existing TaskOutput/TaskStop one.
- **Registry note**: used the spec's suggested `partial` note nearly verbatim
  (lead phrase + `PARTIAL:` clause + `(§4.1, §4.8)`), no leading em-dash.

## Fork / subagent-depth test (Left-open: where it lives)

New file `test/slashcommand-fork.test.ts`. The offline integration layer (fakePi)
CANNOT exercise fork/dispatch because picc's `SubagentRuntime` otherwise calls
`loadRealSdk()` (needs an LLM). To drive the real SlashCommand closure
deterministically I extended the existing in-process-only `PiccTestSeam` with an
optional `sdk?: PiSdk`, passed through to `new SubagentRuntime({ sdk: testSeam?.sdk })`
— undefined in every non-test path, so production behavior is unchanged. This was
the minimal seam that lets the fork test hit the ACTUAL tool rather than a
reconstruction. The test then:
- invokes `/fork-research …` on the main SlashCommand tool → asserts
  `details.forked`, `details.agent === "researcher"`, forked finalMessage;
- dispatches `future-agent` (inherits ALL tools → granted SlashCommand) through the
  Agent tool and asserts its created session carries a working `SlashCommand`
  customTool (proves the `allKnownToolNames` MUST-FIX + the subagent grant block),
  then, via the seam-captured `subagentRegistry`, asserts the subagent registered at
  depth 1 and the fork it launched through its OWN SlashCommand registered at depth
  2 — proving depth propagation / nested-limit applicability.

## Friction / surprises

- **Session-wide dedup fingerprint is shared** by the Skill tool, SlashCommand, and
  the user-typed transform (`lastSkillRenderHash`, keyed by skill name). This makes
  a naive "SlashCommand result equals Skill tool result for identical input"
  assertion impossible in one session — whichever runs second returns the dedup
  note. The happy-path equality test works around it by rendering `expected` with a
  UNIQUE args set, then a throwaway Skill call with DIFFERENT args to bump the
  fingerprint, so the SlashCommand re-render of the original content is not
  collapsed → byte-identical to `expected`.
- **Plugin skill `${CLAUDE_PLUGIN_ROOT}` substitution** could not be re-asserted via
  SlashCommand on a full render: `plugin-skill` takes no args, so its render is
  fixed and always dedups after the existing Skill-tool test (t5) renders it once.
  The plugin test therefore asserts resolution via `details.skill ===
  "bundled-fixture-plugin:plugin-skill"` for both the bare `/plugin-skill` and the
  `:`-form `/bundled-fixture-plugin:plugin-skill` (findByName parity). Substitution
  itself is already covered by t5 on the shared activation path.
- `future-agent` was the only fixture agent with no `tools:` frontmatter (inherits
  all), which is exactly what the subagent-grant test needs; the fixture is
  read-only so this was the natural choice.
