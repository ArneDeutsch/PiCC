## Key decisions
- **Helper home**: `scopedBackgroundTools` lives in `background-tasks.ts` (where the factories
  live) — inside the writable surface, keeps the scope seam in one module.
- **Owner id is runtime-derived, never test-supplied.** The test injects a fake SDK via the
  widened `onWired` seam and drives the coordinator's *registered* Agent tool. Each subagent's
  own agent id is minted at subagents.ts:559 and flows through :913 → `customToolsFor` →
  `scopedTo(ownerAgentId)` AND through the nested Agent tool → `start`'s `owner`. The test only
  ever passes prompts and task ids; it captures the subagent's injected tools from
  `fakeSdk`'s `session.customTools`. This is the faithful route the spec required (not the
  forbidden "widen onWired to call customToolsFor with a test-chosen ownerAgentId").
- **setSdkForTest over widening deps in index.** The runtime already resolves `deps.sdk` first;
  a tiny test-only setter is the lowest-cost injection point. Reachable only through the
  in-process `onWired` seam, never the project-loading path.

## Non-leak assertion correction (friction / surprise)
- First cut asserted the refusal message `not.toContain(coordTaskId)`. It FAILED: the standard
  "Unknown task_id" message echoes the *queried* id back in its prefix. That echo is the
  caller's own input — not a leak. Corrected the test to check only the **"Known background
  tasks:" list** (must contain own id, must not contain sibling/coordinator ids) and added an
  indistinguishability check: querying a genuinely-never-issued id (`task-99999`) yields the
  identical known-list, proving a foreign task's existence is unobservable through the refusal.
  Good lesson: the non-leak contract is about the *known set*, not about scrubbing the echoed input.
