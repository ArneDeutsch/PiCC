# t02 execution log — wire the fork path

## What shipped

Four edits in `src/index.ts` + two new offline-integration test files. Imported
`presentDispatchResult` and the `PiSdk` type from `src/runtime/subagents.ts` (t01's
helper) — no re-implementation of the outcome mapping.

- `forkDispatch` gained a trailing `abortSignal?: AbortSignal`, forwarded into
  `dispatch({ …, abortSignal })`. It still only forwards into `dispatch` (which always
  resolves a `DispatchResult`), so it resolves-never-rejects — both callers rely on that.
- Skill-tool `execute` gained a 3rd positional `signal?: AbortSignal`, threaded into
  `forkDispatch`. Replaced the `if (!result.ok) throw` partial-dropping bug with the helper
  (`allowResumeTrailer:false`): `kind:"failure"` → `throw p.message`; `kind:"result"` →
  content `p.text` with `details {forked:true, agent:result.agentName, cutOff:p.cutOff}`.
- Input-hook fork branch passes `ctx.signal` into `forkDispatch` and folds EVERY outcome
  into the transform text (never throws — a throw would hit the handler's catch and send the
  raw unexpanded `/skill` to the model).
- `PiccTestSeam` gained an optional `sdk?: PiSdk` input field; read into
  `new SubagentRuntime({ …, ...(testSeam?.sdk ? { sdk: testSeam.sdk } : {}) })` at the
  construction site. Extended the SECURITY comment block to name it. In-process only.

## Key decisions

- **sdk-seam field shape:** `PiccTestSeam.sdk?: PiSdk` (the exact dep type the runtime already
  consumes lazily). Plumbed straight into `deps.sdk`; unset ⇒ `loadRealSdk()`. Spread
  conditionally so an absent field never sets `sdk: undefined` explicitly (cosmetic parity
  with how the field is otherwise omitted). `fake-pi`/`fake-sdk` route it unchanged: tests
  build a `fakeSdk()` handle and pass `sdk: h.sdk` as the second `picc()` arg — the fake SDK
  is the same `PiSdk` shape `fake-sdk.ts` already produces for the unit tests, so no changes
  to either helper were needed.
- **Input-hook wording:** kept the existing success envelope verbatim —
  `` `The ${skill.name} skill ran in a forked subagent. Its result:\n\n${p.text}` `` — used
  for BOTH completed and failed-with-partial (`kind:"result"`), since `p.text` already carries
  the partial + cut-off note for the cut-off case. For `kind:"failure"` (failed-no-output /
  aborted) chose `` `The ${skill.name} skill (context: fork) did not finish: ${p.message}` ``
  ("did not finish" reads correctly for both no-output failure and abort, and names the cause).
- **Skill-tool `details.cutOff`** is set from `p.cutOff` (mirrors the Agent tool). Success →
  `cutOff:false`, failed-with-partial → `cutOff:true`.
- **Left-open "pass or omit ctx.signal":** passed it through (recommended option — correct when
  defined, harmless when `undefined`). Documented inline that at the input-hook stage
  `ctx.signal` is `undefined` for a typed `/forked-skill`, so this does not make a typed
  expansion Esc-cancellable (t03 documents the harness limitation; not hidden here).
- **Test-file split (left open):** two files. Consumer cases 1–7 in
  `test/fork-failure-handling.test.ts` (fresh `wire()` + injected fake SDK, no module mock).
  The seam invariant in a SEPARATE `test/fork-sdk-seam.test.ts` because it needs a `vi.mock`
  of `@earendil-works/pi-coding-agent`, which is file-scoped — isolating it keeps the mock out
  of the injected-fake-SDK consumer tests.

## Friction / surprises

- The seam-invariant test's first module-mock attempt returned a hand-built object and blew up
  because the real SDK module has many other exports the rest of the codebase imports
  (`defineTool`, the built-in tool factories, …). Switched to a partial mock via
  `importOriginal()` that overrides ONLY `createAgentSession` to throw a sentinel. dispatch's
  catch-all (`subagents.ts:1285`) wraps that throw into a resolved `failed` result, so the
  single-arg `picc(pi)` fork surfaces the sentinel through the real Skill tool — proving it
  reached `loadRealSdk()` (a fake seam SDK would never touch that module).
- Confirmed the abort path is provable offline: the never-settling `gate` +
  `setTimeout(10)` + `controller.abort()` pattern from `subagent-outcomes.test.ts` works at the
  `execute` boundary; if the signal threading were dropped the test would hang, not pass.
- Asserted on the abort WORDING (`"aborted"`), not the synthetic `fork:<skill>` agent name.
