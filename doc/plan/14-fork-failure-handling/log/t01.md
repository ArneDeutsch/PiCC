## Behaviour-preservation notes

- The helper folds the old three inline branches into four logical outcomes but the byte
  output is identical:
  - failed-with-partial → `kind:"result"`, `cutOff:true`, same `appendCutOffNote` + optional
    single-`\n` `agentTrailerLine(completed:false)` on resumable.
  - failed-no-partial / aborted → `kind:"failure"`; trailer frame only when
    `outcome==="failed" && resumable` (aborted stays bare — matches the old ternary).
  - completed → `kind:"result"`, `cutOff = truncated === true`; non-resumable verbatim,
    resumable+truncated rides inside the frame (single `\n`), resumable completed opens its
    own `agentTrailerFrame(completed:true)`.
- Consumer keeps two separate `kind:"result"` return sites (failed-with-partial vs
  completed) so `details` (the `error` field on the cut-off path, the background `note` on
  the completed path) is byte-identical to before. The completed branch's `cutOff` now reads
  `presentation.cutOff` (equal to the old `result.truncated === true` on that path).
- `allowResumeTrailer` gates trailers on top of `result.resumable` via
  `result.resumable && opts?.allowResumeTrailer !== false` (default true). The Agent tool
  passes the default; t02 will pass `false` for forks.
- Helper is total: reads `result.finalMessage ?? ""` before `.trim()`; never throws; never
  re-applies `capErrorText` (errors arrive pre-capped).
