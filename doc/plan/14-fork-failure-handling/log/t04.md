# t04 — typed /forked-skill Esc cancellation (interactive mode)

Added post-close at the user's request (former follow-up 1 / remaining scope of #11), done
directly rather than filed as a ticket.

## What / how

- The typed top-level `/forked-skill` runs synchronously inside the `pi.on("input")` handler,
  BEFORE the turn streams, so `ctx.signal` is `undefined` there (no active run / abort
  controller). That was the reason the typed route wasn't Esc-cancellable.
- Pi exposes `ctx.ui.onTerminalInput(handler)` — "listen to raw terminal input (interactive
  mode only)", returns an unsubscribe fn; the handler may return `{ consume?: boolean }`
  (`node_modules/@earendil-works/pi-coding-agent/dist/core/extensions/types.d.ts:49,77`).
- The input-hook fork branch (`src/index.ts` ~1171) now, when there is no `ctx.signal` and
  `onTerminalInput` is available, creates its own `AbortController`, subscribes, and aborts on
  a **lone** Esc (`data.length === 1 && data.charCodeAt(0) === 0x1b` — Esc-prefixed sequences
  like arrow keys are longer, so they don't cancel), consuming that keypress. The controller's
  signal is threaded into `forkDispatch`; the watch is unsubscribed in a `finally`.
- Print/RPC modes expose no `onTerminalInput` and have no Esc → the fork runs to completion
  (documented, not silently degraded).

## Testing

- Offline test (`test/fork-failure-handling.test.ts` case 8): a fresh `wire()`d extension with
  a fake TUI `ctx` (custom `ui.onTerminalInput` capturing the handler, `mode:"tui"`,
  `signal:undefined`) fires a `/fork-research` input against a never-resolving gated fork; the
  test polls until the hook subscribes, sends an ESC-prefixed arrow sequence (must NOT cancel),
  then a bare Esc (must cancel + return `{consume:true}`), and asserts the transform reports
  "did not finish … aborted", no raw `/fork-research` leak, and the watcher was unsubscribed.
- Note: the fixed 10ms sleep used by the direct-`execute` abort tests was flaky for the
  input-hook path (more awaits before subscription); replaced with a poll loop.

## Honest residual (surfaced to the user, in review.md)

- The **wiring** is proven offline (Esc byte → abort → aborted). What is NOT verified is **live
  end-to-end delivery**: whether a real terminal Esc reaches `onTerminalInput` listeners while
  the input-event handler is being awaited in a live TUI. It is the documented purpose of the
  API, and the listener is event-driven (so an async-awaited handler shouldn't starve it), but
  I could not confirm it from Pi's minified bundle and cannot script a live Esc in the suite.
  **Recommend a one-time manual smoke test** (interactive picc, type a slow `/forked-skill`,
  press Esc) before fully trusting the live path / before closing #11 on this basis.
