# F06 observations

- 2026-07-14 (Phase 2 scouting): A prior **cancelled epic F03** (`feature/03-github-workflow`, unmerged) already attempted a *superset* of this — but issue-*mandatory* and ballooned into channels/forks/releases. Discovering it early (via `git branch --list feature/*`, since it had no `doc/plan/03` folder on main) prevented rework and clarified the lean/optional stance. Lesson: branch-global state can carry design history that isn't in `doc/plan/` on main — scout branches, not just the plan folder.
- 2026-07-14 (planning): This is a **prose-only skill change with a real security surface** (prompt injection + shell injection from public-repo ticket text). No `src/`, so the authored prose is the *only* guardrail — omission = vulnerability. Reinforces that "docs-only" ticket features still need a security review pass.
- 2026-07-14 (plan review): The PR `--title` is the one untrusted-data sink that **can't** use `--body-file` (`gh pr create` has no `--title-file`). Nearly missed — the model-authored-ASCII rule originally scoped only the branch slug. Caught by the security plan reviewer. Lesson: enumerate *every* sink that takes untrusted text, and note which can't be file-fed.
- 2026-07-14 (diff review): **Idempotency asymmetry** — Rule 9 guarded the kickoff comment and `gh pr create` but not the Phase 9 *summary* comment; a resumed run would double-post it publicly. Found independently by the adversarial `generalist` and `user-experience` reviewers. Root cause was in the *spec* (Rule 9 + acceptance named only two of the three public writes). Lesson: when a feature adds N public side-effects, the resume guard must cover **all N**, listed explicitly.
- 2026-07-14 (diff review): **Cross-rule contradiction** — Rule 9's "refresh the summary on the PR" implied `gh pr edit`, which Rule 5's three-action allow-list forbids without approval. Two rules authored separately, never cross-checked. Reworded to post the summary as the ticket comment only. Lesson: when rules constrain each other (an allow-list vs an action instruction), cross-check them at authoring time.
- 2026-07-14 (diff review): **Ordering seam** — Phase 8 previews/​confirms the summary text before `review.md` (a listed source of that text) is written in Phase 9. Reconcilable (the underlying `observations.md`/logs exist at preview time) but the prose didn't say so; clarified that the preview is authored from existing material and is the exact bytes posted, re-confirmed if changed.
- 2026-07-14 (process): Dispatch "read first" paths pointed at the main-checkout `doc/plan/06-...`, but those files exist only in the worktree. The implementer read them in the worktree without trouble — harmless, but future dispatches should give worktree-relative plan paths.
- 2026-07-14 (opportunity): Every reviewer noted the real enforcement of the `gh`/`git` allow-list is PiCC's **permission engine** gating Bash, not the prose — if a project's `settings.json` broadly allows `Bash(gh:*)`, Rule 5 is advisory only. A future hardening: a recommended permission profile for the ticket path (deny `gh pr merge`, force-push, `gh issue create/close`).
