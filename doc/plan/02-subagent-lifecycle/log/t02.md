## Decisions on "Left open" items

- **Agent ID format:** `agent-` + 12 lowercase hex chars (`crypto.randomBytes(6)`),
  e.g. `agent-3fa9c2d1b4e5`. Satisfies Pi's session-id validator, is short enough for
  prose, and the strict shape doubles as the resolver's path hardening (a positive
  allowlist regex rejects separators/`..`/drive-UNC/reserved names outright).
- **Directory/filename scheme:** for main transcript `<dir>/<base>.jsonl`, subagent
  transcripts live in the sibling directory `<dir>/<base>.subagents/`, one file per
  agent named by Pi itself: `<stamp>_<agentId>.jsonl` (via `create(cwd, dir, {id})`).
  The agent ID is embedded verbatim in the filename; the exported resolver
  (`resolveSubagentTranscript(mainSessionFile, agentId)`) validates the ID, scans the
  dir for the `_<agentId>.jsonl` suffix and returns the newest match (normally unique).
  Chosen over a fully deterministic `agent-<id>.jsonl` name because Pi's blessed
  `create()` path owns the naming — no reliance on `setSessionFile`'s --session-flag
  side path. Sibling-dir layout keeps subagent files invisible to Pi's own session
  listing/`--continue` (non-recursive `.jsonl` scan) while staying discoverable next to
  the main transcript. No agent *name* is embedded in filenames, so no name
  sanitization was needed.
- **Trailer wording:** `\n\n---\n[agent <id> completed — resumable via SendMessage]`
  appended to the verbatim foreground content and TaskOutput text of resumable agents;
  the cut-off/failed variants drop the word "completed" and (foreground) ride inside
  the existing cut-off `---` frame as an extra line. Background start message carries
  `(agent: <label>, agent id: <id>)`.
- **Where the helpers live:** new `src/util/subagent-transcripts.ts` (mint/validate/
  dir-derivation/resolver/trailer-line). Shared by subagents.ts AND background-tasks.ts
  — a util import keeps the t01 house rule (no value-level import between those two
  modules) without duplicating code this time. The trailer formatter is admittedly not
  a *path* helper; placed there anyway as the one shared t02 surface (noted as a mild
  stretch of the writable-surface wording).

## Behavior notes

- `DispatchResult` gains `agentId` (required — every exit path mints/carries one),
  `transcriptPath?`, `resumable`. `BackgroundResultLike`/`BackgroundTaskRecord` mirror
  them (optional, structural). `registry.start()` gained an optional `agentId`
  parameter: the background Agent tool pre-mints the ID (dispatch accepts
  `opts.agentId`) so the start message can deliver it before the un-awaited dispatch
  settles; the settled result remains authoritative.
- **Resumable semantics:** persisted transcript AND not a one-shot builtin. Builtin
  one-shot detection is `agent.builtin === true && name in {Explore, Plan}` — a
  project agent named Explore resolves first, lacks the marker, and is resumable.
  Failed-with-transcript runs stay `resumable: true` (coordinator may follow up on the
  cut-off run — t04 decides policy); **aborted** results keep the actual capability
  flag but no trailer is ever delivered for them (tool throws); the **catch-all**
  (unexpected internal error) is conservatively `resumable: false`.
- **Fallback ladder** (degrade, never crash): main session file unknown (print/
  `--no-session`, tests) → info diagnostic; SDK without `persistedSessionManager` →
  info; `create()` throwing → warning with the error text. All three run in-memory,
  complete normally, and are non-resumable (verified by tests).
- **transcript_path parity (corrected in review round 2 — see the dedicated section
  below):** subagent hook events (SubagentStart/SubagentStop, scoped Stop, and the
  guard's Pre/PostToolUse fired from inside the dispatch) keep the **MAIN** session
  transcript_path, exactly as Claude Code does — PiCC does NOT re-point them at the
  subagent's own transcript. `agent_id` + `agent_type` are still injected on every
  in-dispatch hook event via the central `injectIdentity` choke point (no type change:
  HookPayload has an index signature). The subagent's own transcript stays discoverable
  via the exported resolver + the ID trailer.
- context:fork skill dispatches get transcripts too (same dispatch path) but their
  results are returned without a trailer (fork return contract untouched); whether
  forks should be SendMessage-addressable is left to t04. **Left open.**

## Cleanup / privacy (spec-required notes)

- **No age-based cleanup in v1:** subagent transcript dirs accumulate under Pi's
  sessions dir exactly like Pi's own session files, which Pi does not reap either;
  the worktrees `reapOrphans` pattern exists if wanted later. t07 should mark
  `setting.cleanupPeriodDays` accordingly (worktrees-only).
- **Transcript privacy:** same exposure class as Pi's/Claude Code's own transcripts —
  plaintext JSONL under the user's home/agent dir, same permissions; PiCC adds no new
  exposure surface, only more files of an existing kind.
- **Trailer is advisory, not authenticated** (in-band): a subagent could emit a forged
  look-alike line in its own prose; the dispatch registry (t04) stays the source of
  truth for what an ID reaches, bounding impact to misdirected (legitimate) delivery —
  the same property Claude Code has.

## Friction / surprises

- TS7 (native tsc) has no `path.PlatformPath` in its bundled node types — used
  `typeof path.win32` as the flavor type instead.
- `assertValidSessionId` is not exported from the package root (only from the internal
  session-manager module), so the runtime pin asserts `create`/`open` existence and
  the minted-ID acceptance is proven live by the transcript tests instead.
- Pi's lazy flush means a dispatch that dies before ANY assistant message leaves no
  file (the allocated `transcriptPath` then dangles); the resolver returns undefined
  for it and t04 refuses via file absence. Terminal API errors DO produce an assistant
  message, so real failure transcripts persist.
