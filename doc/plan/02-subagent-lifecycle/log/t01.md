## Decisions on "Left open" items

- **Error-string allocation (wording pin vs raw errorMessage):** the spec pins the
  foreground throw as `Agent terminated early due to an API error: <error>` but also
  says `error` = capped Pi errorMessage. Those conflict at the throw site, because the
  existing `!ok → throw result.error` channel is shared with pre-prompt failures
  (depth cap, hook block) whose messages must NOT claim an API error. Resolution:
  dispatch sets `error = "Agent terminated early due to an API error: <capped
  errorMessage>"` for stopReason-"error" runs at classification time, and the tool
  throws `result.error` verbatim. Net effect: the pinned wording reaches the model
  exactly for API deaths; pre-prompt failures keep their self-describing errors; one
  error channel, no second field. The fixed prefix is classification, not
  request/header/env enrichment.
- **Cut-off note shape** (`appendCutOffNote`, exported from subagents.ts):
  `<text>\n\n---\n[subagent cut off] <note>`. Used for failed-with-partial (note =
  the API-error sentence) and for stop-reason-"length" truncation (note names the
  token limit). Truncation also pushes a warning diagnostic — never silent.
- **Abort wording:** post-prompt `Subagent "<name>" was aborted before completing its
  task.`; pre-start paths keep `... was stopped before it started.` Both distinct
  from the API-error wording (asserted in tests).
- **Partial-output join format:** all assistant-turn texts (including any partial
  text on the dying turn), blank-line (`\n\n`) separated, empties skipped.
- **PiSession messages:** extended structurally via exported `PiSessionMessage`
  (`stopReason?`/`errorMessage?` optional) — real AssistantMessages (required
  stopReason) stay assignable, simple fakes too.
- **Mock-openai error API:** `Turn.error = { status, message?, sticky? }`; sticky
  defaults **true** and sticky turns are never consumed, so Pi retries (and any later
  matching request) keep hitting the error instead of the `{text:"done"}` fallback.
- **TaskOutput failed shape:** `Background task <id> (<label>) failed: <error>` plus
  `\n\nPartial output before the failure:\n<partial>` when partial output exists
  (kept local to background-tasks.ts rather than importing the cut-off-note helper —
  avoids a value-level import cycle with subagents.ts).
- **Background aborted mapping:** a dispatch that itself classifies `aborted` (e.g.
  external abort without TaskStop) lands status `"stopped"` with the abort reason in
  `record.error`; the existing TaskStop-marked-stopped path still discards late results.

## Deviations / notes

- The genuinely-unusable-agent pre-prompt path (`!agent`, subagents.ts) is classified
  `failed` per spec but is **unreachable in practice** (builtinAgents() always
  contains general-purpose, even under CLAUDE_CODE_DISABLE_EXPLORE_PLAN_AGENTS), so it
  has no dedicated unit test — it cannot be triggered through the public API.
- **pi-contract type pins:** `npm run typecheck` excludes test/ and vitest's esbuild
  transform does not typecheck, so inline type-level pins would be decorative. The
  pins live in `test/helpers/pi-contract-pins.ts` (never executed) and
  `test/pi-contract.test.ts` compiles them with the real tsc
  (`test/helpers/pi-contract-pins.tsconfig.json`). Surprise: the repo has
  **TypeScript 7.0.2** (native), whose JS API has no `createProgram` — the test
  shells out to `typescript/bin/tsc` instead. Verified the pin fails loudly by
  temporary sabotage (extra StopReason member → test failed with tsc diagnostics),
  then restored.
- **Out of t01 scope, noticed:** `src/index.ts` context:fork dispatch (`:658`, `:922`)
  throws/reports on `!result.ok` — a failed fork WITH partial output loses the
  partial text there (only the Agent tool got the 2.1.200 partial+note mapping;
  index.ts is outside t01's writable surface). Candidate for t02+ or follow-up.
- SubagentStop-loop re-prompts are also classified after each prompt (an API death
  during hook-forced continuation reports failed, not a stale success) — spec's
  "every dispatch exit path" read broadly.
- Old gatedSdk fake semantics changed slightly with the shared builder: `abort()` now
  produces a stopReason-"aborted" assistant message (like real Pi) instead of
  releasing the gate into a normal reply; all existing background tests still pass
  unchanged in their assertions.

## Review-fix round (accepted findings, applied 2026-07-12)

- **Tests added** (test/subagent-outcomes.test.ts, now 24 tests): catch-all
  (`createAgentSession` rejecting with an >500-char message → failed, error capped);
  abort during worktree entry (isolation "worktree", enter() fires the signal →
  aborted, no session created, worktree keep-exited); API death during a
  SubagentStop-forced continuation (→ failed with the pinned wording, not a stale
  success); signal during SubagentStop-hook evaluation (→ aborted, see below).
- **Behavior — abort-race consistency:** a signal observed at the SubagentStop loop
  (previously `break` → completed when the hook was blocking, and completed via the
  `!block` break otherwise) now returns the same aborted result as terminalOutcome's
  `abortSignal.aborted` arm. The check sits BEFORE the `!block` break, so
  signal-aborted wins on every settle path; aborted results are discarded by
  contract, so the old completed-looking result could leak past an abort.
- **Hardening — capErrorText** now collapses control characters and whitespace runs
  to single spaces (`/[\s\p{Cc}]+/gu`) before the 500-char cap: a provider-controlled
  errorMessage can no longer fabricate a multi-line fake cut-off frame. Cap test
  extended with a newline/BEL payload asserting exact single-line output.
- **Hardening — background-tasks rejection handler** routes `err.message` through the
  same cap. Decision: DUPLICATED the 3-line helper in background-tasks.ts (with a
  cross-reference comment both ways) instead of importing from subagents.ts —
  consistent with the earlier BackgroundResultLike decision to keep this module free
  of value-level imports from subagents.ts (a later value import there would
  otherwise create a real cycle).
- **Hardening — abort listener:** `void live.abort?.()` →
  `Promise.resolve(live.abort?.()).catch(() => {})` so a rejecting abort() cannot
  become an unhandled rejection (sync throws still caught by the surrounding try).
- **Polish:** `ok` doc comments on both result types now read "True iff
  `outcome === "completed"`."; catch-all uses null-safe `(err as Error)?.message`;
  `appendCutOffNote` is file-local again (no test imported the export).
- **fake-sdk typing (contained):** `customTools` is now `FakeCustomTool[]` (name +
  5-arg execute returning content/details) and the `as never` deps cast is gone —
  `makeSubagentRuntime` builds a typed `SubagentRuntimeDeps` from
  `SubagentRuntimeOverrides` (`Partial<Omit<Deps, "hookRunner">>` plus a fire-only
  `FakeHookRunner` facade, one commented narrow cast where it meets the class-typed
  deps field). Only ripple: runtime-core.test.ts's local `makeRuntime` overrides
  param went from `Record<string, unknown>` to the new type (2-line change).
- **Friction:** an early edit smuggled raw BEL control characters into the test
  source (tool-layer unescaping of `\u0007`); replaced with explicit `\u0007` source
  escapes and verified the tree contains no raw control chars.
- **Re-verification:** `npm run typecheck` green; full `npm test` green — 35 files
