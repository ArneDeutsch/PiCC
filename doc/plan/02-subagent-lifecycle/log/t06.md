## Field mapping (spec `usage?` shape ← Pi `SessionStats`)

`DispatchUsage` = `{ inputTokens?, outputTokens?, cacheReadTokens?,
cacheWriteTokens?, costUsd? }`, all NUMBERS. `usageFromStats(stats)`:
`inputTokens ← tokens.input`, `outputTokens ← tokens.output`,
`cacheReadTokens ← tokens.cacheRead`, `cacheWriteTokens ← tokens.cacheWrite`,
`costUsd ← cost`. Each field is set only when Pi reported a `number` — absent
fields are OMITTED (never invented as zeros). If nothing maps, usage is
`undefined` (not `{}`).

## Where the capture happens (the spec's mandated seam)

`captureUsage()` (a dispatch-local closure over the live `session`) reads
`session.getSessionStats?.()` best-effort into a mutable `capturedUsage`. It is
called at each SESSION-BEARING result-return — the terminalOutcome failed/aborted
returns, the completed return, the SubagentStop-loop abort return, and the
catch-all — i.e. AFTER the last `prompt()` and BEFORE the result literal is
built, exactly as the spec requires (a finally-only capture has nowhere to
attach to the returned DispatchResult). The `finally` calls `captureUsage()` once
more (before `session.dispose()`) as an idempotent safety net for the registry
record. Pre-session guards (bad id / no agent / depth / pre-start abort / resume
reopen-fail) have no session → usage stays undefined, which is correct.

The structural `PiSession` interface gains `getSessionStats?()` (optional), so
fakes/older SDKs that omit it → usage undefined, no crash (verified by the
`noGetSessionStats` test).

## Mirrors kept in sync

- `DispatchResult.usage?: DispatchUsage` (canonical, subagents.ts).
- `BackgroundResultLike.usage?` + `BackgroundTaskRecord.usage?` (structural
  `UsageLike` in background-tasks.ts — the module keeps its no-value-import
  relationship with subagents.ts, matching the existing `BackgroundResultLike`
  mirror idiom). `record.usage = result.usage` is set in the settled handler
  BEFORE the stopped-branch early return, so a stopped/aborted task still reports
  what its partial run cost.
- `SubagentRegistryRecord.usage?` + `.outcome?` (structural `SubagentUsage` /
  `SubagentOutcome` in subagent-registry.ts — the registry stays dependency-free
  of the runtime). `markSettled(agentId, { outcome, usage })` records both at

Duplicating the ~5-field usage interface three times (rather than a shared
import) matches the codebase's established structural-mirror pattern (t01's
`BackgroundResultLike`, the duplicated `capErrorText`) and keeps
background-tasks / subagent-registry free of runtime coupling.

## Human-visible surfaces

1. **Foreground (Agent tool):** `details.usage = result.usage` (the numeric
   object). t03's `renderResult` footer renders it via `formatUsageLine` →
   `formatUsageCompact`. I rewrote `formatUsageLine` to delegate to the shared
   `formatUsageCompact` (kept its `string`/`u.text` fast paths) so the split
   token fields render — the old slot only understood `totalTokens`/`cost`. The
   legacy shape still renders ("1200 tokens" test unchanged).
2. **Background (TaskOutput):** a compact `usage: <line>` is appended to the
   result text for any settled task with usage (including stopped — the cost of
   the aborted run), OUTSIDE the verbatim body and after any t02 agent-ID
   trailer, and `details.usage` is set. (The completed TaskOutput text already
   rode the t02 trailer outside the verbatim frame, so a trailing metadata line
   is consistent — the verbatim-return contract for `finalMessage` is untouched.)
3. **Control command `/usage`** (see "Left open" for the name): aggregates the
   dispatch registry (t04) into a per-subagent breakdown — each record's agent
   id, type, outcome, usage line, and transcript path — plus a **Session total**
   that sums each field only across records that reported it (an absent field
   stays absent, never a fabricated zero). This is the headline deliverable: the
   per-subagent view the user asked for.

The shared formatter `formatUsageCompact(usage)` lives in `subagent-progress.ts`
(the neutral display-text util already imported by subagents.ts and
background-tasks.ts; index.ts imports it too), so every surface reads identically.

## Compact usage-line format (Left open — decided)

`in 100 · out 50 · cache read 20 · cache write 10 · $0.0123` — labeled segments,
only present fields, joined by ` · `. Cost via `$` + `toFixed(4)` with trailing
zeros trimmed (`$0.03`, `$0.5`), and `$0.00` for a real zero cost. Legacy
`totalTokens` shape renders `1200 tokens`. Returns undefined when nothing
renders, so callers drop the line entirely.

## Control-command name/shape (Left open — decided)

Named **`/usage`** — the token/cost breakdown is the headline value and the name
signals it directly. Not reserved by Pi (not in `RESERVED_NAMES`; Pi's own
`/session` is separate). Added to `CONTROL_COMMANDS`, the `runControlCommand`
switch, and `RESERVED_NAMES` (so a project skill can't shadow it). Output:
`PiCC — per-subagent usage this session (N dispatched):`, then per record
`  <id> (<name>) — <outcome>` / `    usage: <line>` / `    transcript: <path>`,
then `  Session total: <line>`. Empty registry → "No subagents have been
dispatched this session".

## Partial-usage policy (Left open — decided)

**Yes — failed AND aborted runs report their partial usage when Pi provides it.**
That directly answers "what did the failure cost me". Verified: the failed-run
and aborted-run dispatch tests both assert `result.usage` is populated, and the
background stopped/aborted record keeps its usage.
