## Decisions on the "Left open" items

- **Rolling-tail length/format:** default 12 lines, 200-char per-line cap
  (`DEFAULT_MAX_TAIL_LINES`/`DEFAULT_MAX_LINE_LENGTH`, both constructor-overridable).
  Tail entries: `> <ToolName> (<argHint>)` on tool start, `  <ToolName>: <first
  result line>` (or `  x <ToolName> failed: …`) on tool end, and the subagent's
  own assistant lines on `turn_end`. Newest-last; the cap keeps the most recent.
- **Current-activity line:** priority-free single string set by the latest event
  — `running <Tool>…`, `waiting: API retry N/M` (silent-wait visibility),
  `retry succeeded; resuming…`/`retry failed`, a streaming assistant preview
  (last non-empty line) on `message_update`, `thinking…` on `turn_start`,
  `working…` after a tool ends.
- **renderResult layout:** PARTIAL → `Agent(<agent>) running…` header + tail
  lines + `… <activity>`. FINAL → outcome badge (`● completed` / `✗ failed
  (partial output preserved)` / `■ aborted`, colored via theme) + the verbatim
  message body (wrapped, unstyled so width-slicing can't corrupt color codes) +
  a muted footer: `transcript: <path>`, `usage: <…>` (t06 slot), `resumable via
  SendMessage`. Background-start results get an `Agent → background` header. All
  fields optional and rendered only when present; empty `details` degrades to
  just the content text. The t06 usage slot is defensive
  (`formatUsageLine`): string as-is, object via `text`/token/cost fields,
  nothing when absent or an unknown shape — documented as the t06 coordination
  point.
- **onUpdate throttling:** the condenser is pure/deterministic and dedupes —
  `consume()` returns `true` only when the visible snapshot actually changed, so
  the dispatch subscriber emits `onProgress` only on real change.
  `message_update` updates ONLY the single-line activity preview (never grows
  the tail token-by-token). Honest accounting (FIX-C): this bounds MEMORY (one
  activity line, not a token-by-token buffer) but does NOT bound the emission
  RATE — each streaming token that changes the preview yields one `onUpdate`,
  so in print/RPC mode the model sees one partial per streaming token; the
  interactive UI coalesces renders on its own. Rate-limiting via timers was
  left open on purpose (keeps the condenser deterministic/timer-free). Baseline
  snapshot initialized in the ctor so an empty `message_update` correctly
  reports "no change".
