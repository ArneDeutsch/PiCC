## 2. Wiring-seam revert-catching test — did BOTH approaches (deliberate)
The spec prefers the booted-harness assertion "if reachable — it covers the threading too."
But a booted assertion runs on Linux CI, where `toNativeSafeTempForm` is a no-op, so the
realpath→transform ORDER swap is invisible to it and CANNOT be caught by a booted test. The
"Testing" gate requires the order swap to go RED. So the honest reading needs the pure helper
for the computation regressions AND the booted test for the threading. Implemented both, minimal.

- **Extracted pure helper** `computeSessionScratchDir(io: ScratchDirIo)` in src/util/env.ts:
  injectable `env / tmpdir / mkdtemp / realpath / join / platform`. Encodes the load-bearing
  order: `root = CLAUDE_CODE_TMPDIR || tmpdir()` → `mkdtemp(join(root,"picc-scratch-"))` →
  `realpath` → `toNativeSafeTempForm(...)`. index.ts's scratch-dir creation now CALLS this helper
  with the real fs/os/path deps (so the production path is the thing under test), replacing the
  previously-inline block. Dropped the now-unused `toNativeSafeTempForm` import from index.ts.
- **Helper unit tests** (test/subprocess-env.test.ts, new `computeSessionScratchDir` describe):
  - (a) `CLAUDE_CODE_TMPDIR wins`: asserts the `mkdtemp` template is rooted at
    `CLAUDE_CODE_TMPDIR`, not `tmpdir()`. **Catches: CLAUDE_CODE_TMPDIR honoring removed** —
    verified RED by changing the root to `io.tmpdir()` only.
  - (a') fallback-to-tmpdir when unset.
  - (b)+(c) `realpath BEFORE transform`: mkdtemp returns a RAW backslash path, realpath returns a
    DIFFERENT REAL backslash path; asserts `realpath` received the RAW mkdtemp output (not a
    forward-slashed one) AND the result is the forward-slashed REAL path with no backslashes / no
    RAW. **Catches: realpath/transform order swapped** (verified RED) AND a missing win32 transform.
  - non-win32: realpath output returned unchanged.
- **Booted wiring test** (test/runtime-core.test.ts, new describe, same real-harness boot pattern
  as the parent-guard test): boots the extension, fires `before_agent_start`, asserts the
  main-session suffix contains `## Scratchpad directory` + a literal `picc-scratch-` path;
  extracts that path; dispatches a real foreground `general-purpose` subagent and asserts its
  system prompt (via the loader's `systemPromptOverride`) contains the section + the SAME path.
  **Catches: main call-site arg dropped** (main suffix loses the section) and **subagent
  call-site arg dropped (the SHOULD-1 gap)** — verified RED by removing the subagent threading.
  - Note: the subagent system prompt is threaded via `DefaultResourceLoader.systemPromptOverride`,
    NOT `createAgentSession` options. The existing `rcMock.created` only captures the latter, so I
    added `rcMock.loaderOptions` and a thin `DefaultResourceLoader` subclass in the module mock to
    capture loader options. (First attempt read `created[].systemPromptOverride` and was RED for the
    wrong reason — undefined; corrected to the loader capture.)
