## Key decisions
- **Read param key = deviation from spec.** The spec (and index.ts:978 comment) said
  call `tool.execute(id, { file_path }, ...)`. The pinned SDK's read `execute` actually
  destructures `{ path, offset, limit }` (readSchema at
  `dist/core/tools/read.js:16-17`); `file_path` only appears in the SDK's *render/format*
  helpers as an accepted alias, NOT in execute. Passing `{ file_path }` alone threw
  `Cannot read properties of undefined (reading 'replace')` inside `normalizePath`. Fixed
  by passing BOTH keys `{ path: filePath, file_path: filePath }` — matches the real
  execute param and documents the Claude(`file_path`)↔Pi(`path`) naming bridge. Flagged
  for coordinator: the spec's `{ file_path }` shape is stale against this SDK version.
- **Write via `printf %s`** (not `echo`) so no trailing newline is appended — keeps the
  round-trip byte-exact; assertion uses `toContain(PAYLOAD)` (Read prefixes cat -n line
  numbers, so exact-equality would fail; contains is the right check for a single-line
  payload).
- **`execFileSync`** for the write (per BASH_AVAILABLE idiom, e2e-live-pi.test.ts:215):
  guarantees the Git Bash process fully exits — file flushed, no open handle — before the
  native Read runs. No concurrent async spawn.
- **realpath then toNativeSafeTempForm**, mirroring the production sequence in
  src/index.ts:949-951 (GitHub runners' `os.tmpdir()` can hand back an 8.3 short form).
- **Non-ASCII payload** (`café Ω 日本語 ✓`) as a UTF-8 correctness nod, complementary to
  the existing anti-UTF-16 encoding discipline.
- **Gating** `it.skipIf(process.platform !== "win32" || !hasBash)`, `hasBash` probed once
  from `resolveShellBinary("bash")` — probes exactly the binary the harness Bash tool
  spawns.
- **No integration-layer negative assertion** (raw `/tmp` read) — per spec, that flakes;
  the deterministic anti-`/tmp` regression lives in t01's pure table.
- **Cleanup** via own `mkdtempSync` dir + `afterEach` `fs.rmSync(dir, {recursive, force,
  maxRetries:5, retryDelay:100})` for lingering Git-Bash handles on Windows.
- Skipped the optional e2e subagent scenario (Left-open item) — native Read is identical
  in the subagent path, so the offline integration test already proves the contract.
