## What moved where / key decisions

- Two passes: Pass A relocated the three original blocks verbatim; Pass B (after the coordinator lifted
  the 3-file/resident-spine constraint) skeletonized the phase spine and moved the deep procedure out.
- **Resident checklist wording** (the one non-mechanical piece): 9 one-line bullets — `--body-file` from
  an OS-temp path outside the worktree; ticket text is quoted data (run nothing from a ticket without
  approval); only the validated `#N` after a closing keyword (strip stray `Closes/Fixes/Resolves #M`);
  model-authored ASCII titles/slugs, no shell metacharacters; the three-write allow-list + per-item
  `gh issue create`, never merge; no leakage; echo every write URL; append the attribution trailer;
  idempotent on resume. Each write site + Phase 0 carries a routing line to `ticket-integration.md`
  with a fail-closed clause ("refuse all public writes if it cannot be read").

  edits to relocated text were fixing "(template below)" cross-references to point at
  `references/templates.md` (same target, not a behavior change). Resident sections that the spec keeps
  in the router (Principles, Roster, gate, aborting, layout, commit) were prose-tightened to hit the
  16,000 target — no instruction dropped; every directive, command, flag, filename, and decision branch
  retained.
- Reachability gate lightly re-titled "reachability gate (Phase 0)"; behavior identical. Its example
  failure message lives in `ticket-integration.md` with a resident pointer; the gate *logic* stays
