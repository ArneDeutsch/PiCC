# t02 — Fork detection & remote-agnostic repo resolution

## Resolved-identities vocabulary (firm output contract)
Settled exactly as the spec mandated, defined in `references/fork.md`:
- `target` — upstream `owner/repo` (issues + PR base); every `gh issue`/`gh pr` uses `--repo <target>`.
- `push` — `owner/repo` the branch is pushed to; `== target` on the maintainer path.
- `pushRemote` — local git remote *name* whose URL normalizes to `push` (found by URL match, never assumed `origin`/`upstream`).
- `targetDefault` — default branch of `target`; Phase 2 bases the feature branch on it.
Maintainer collapse stated explicitly: `target == push == nameWithOwner`, `pushRemote` = the remote pointing at it (`origin` in the ordinary case), `targetDefault` = today's resolved default. Nothing on the maintainer path changes.

## Review fixes (round 2 — correctness bugs verified against live gh 2.96.0 + a fork)
Re-read the corrected t02 spec (now a 5-step algorithm + revised Phase 2 threading) and made `fork.md` / `workflow-detail.md` match. All fixes landed in `fork.md` and `workflow-detail.md`; the router body stayed at 16,684 chars (no resident change needed).

1. **MUST — `parent.nameWithOwner` doesn't exist.** gh's `parent` object exposes only `id`/`name`/`owner.login`, so `target = parent.nameWithOwner` returns null and breaks the fork path. Now derive `target = parent.owner.login + "/" + parent.name` (e.g. `gh repo view <fork> --json parent -q '.parent.owner.login + "/" + .parent.name'`), stated in both step 2 and step 3.
2. **MUST — never bare `gh repo view`.** Restructured the algorithm to enumerate github remotes FIRST (step 1), then classify each with a PINNED `gh repo view <owner/repo> --json ...` (step 2); documented the cli/cli#6792 base-repo-heuristic misclassification (upstream resolves `isFork:false`, silently mislabels a fork as maintainer).
3. **SHOULD — `viewerPermission` on the TARGET, separately.** Step 4 now decides via `gh repo view <target> --json viewerPermission` (a fork you own reports ADMIN on the fork, which is not upstream access). Fixed the enum: no `NONE` (nullable), added `TRIAGE` → fork bucket = `READ`/`TRIAGE`/null-or-absent; maintainer = `ADMIN`/`MAINTAIN`/`WRITE`.
4. **SHOULD — no bare-URL `FETCH_HEAD`.** `FETCH_HEAD` is per-worktree. `fork.md` Phase 2 bullet and `workflow-detail.md` Phase 2 steps 1 & 3 now add the target as a temporary named remote (`git remote add _upstream <target-url>`), fetch it, branch from the shared `refs/remotes/_upstream/<targetDefault>`, then remove the temp remote (or fetch inside the worktree).
5. **SHOULD — no-gh degrade (new step 5).** If `gh` is absent/unreachable and no ticket forces the gate, classification can't run → degrade to today's git-only maintainer resolution (`git symbolic-ref refs/remotes/origin/HEAD`, branch from `origin/<default>`); keeps maintainer + ticketless + no-gh byte-for-byte. `workflow-detail.md` step 1 folds "(incl. the no-gh degrade)" into the maintainer branch.
6. **NIT — redact credentials.** Step 4 STOP-and-ask now strips `user:token@` from `https://…@github.com/…` remote URLs before echoing.
7. **NIT — SSH host-alias + field verification.** Step 1 treats SSH host-alias remotes (`git@github-work:o/r`) as non-github → safe STOP-and-ask degrade; step 2 verifies gh field availability by a trial query, not the `--json` help enumeration.
