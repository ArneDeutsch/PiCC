# t04 — Ticket-creation offer on the ticketless path

## What was built

mirror converges. New reference file `references/ticket-creation.md` carries the whole flow; the
router got three minimal resident additions; `workflow-detail.md`, `ticket-integration.md`,
`templates.md`, and this feature's `feature.md` got the surrounding qualifications.

## Key decisions
- **Anchor placement (Left open):** chose a `Ticket:` metadata line directly under the feature.md
  title (before `## What`) — machine-greppable, stable, one line. Value `<target>#N` for
  given/created tickets, `–` when ticketless.
- **Anchor reader home:** placed in the "No status bookkeeping" principle — that is the router's
  resume/reconstruction spot, so the reader sits next to the existing "reconstruct from git log"
  guidance. Reads feature.md on empty `$ARGUMENTS` before offering.
- **Phase 2 "nothing posted" claim stays literally true:** filing is deferred to Phase 3, so the
  router's Phase 2 line ("Nothing is posted to a linked ticket here") and workflow-detail Phase 2
  needed only a forward-looking exception note, not a correction — kept resident router untouched at
  Phase 2 to conserve headroom. Only Aborting (where a filed issue is already public) required a
  naming qualification resident.
- **Phase 3 FILE step split:** the short hook + `Ticket:` note live in workflow-detail Phase 3; the
  full procedure (dedup, create, synthesized cache with `labels: []`, ref set, anchor) lives in
  ticket-creation.md per the writable-surface note that detail belongs in the new reference file.
- **Reachability = Phase-8 preconditions, silent skip** on any failure (no error, no nudge).
- **Write-contract routed by checkout kind at the accept step** (maintainer PR+comment vs. fork
  compare-URL hand-off), with the fork case explicitly reconciling "the feature issue is the one
  consented write on `<target>`; nothing *else* is auto-posted; the PR is opened by the user".
- **Rule 5** framed the create-offer as the same write as the Phase 8 filing offer (different
  intent), leaving the final shared-wording coherence pass to t05 as the spec directs.

## Review fixes (round 2)
Applied all 5 coordinator-relayed findings; re-read the updated t04 spec's "Resident anchor READER"
bullet and made the router match it.

1. **SHOULD (resume cache re-hydration).** The resident anchor reader now, on adopting the ticket
   path, **re-runs the gate's `gh issue view <N> --repo <target> --json
   number,title,body,labels,state,url,comments`** to rebuild the issue cache this session — the
   synthesized `comments: []` from the filing session is stale on a post-Phase-3 resume (empty
   `$ARGUMENTS`, so Phase 0 never re-runs), which would let Phase 9 double-post the hand-off comment.
   Applies to given-ticket resumes too. Kernel kept terse in `SKILL.md`; elaboration in a new
   "Resume — the anchor reader (adopt AND re-hydrate)" section of `ticket-creation.md`.
2. **SHOULD (sentinel fragility).** The ticketless test now keys on ref **shape**, not the en-dash:
   treat as ticketless unless `Ticket:` holds a valid ref (`<owner/repo>#<int>`, `#<int>`, or an
   issue URL); any placeholder/blank (`–`/`-`/`—`/empty/missing) → offer. Router wording updated; the
   template's and feature.md's `Ticket: –` stay as-is (valid non-ref placeholders).
3. **NIT (UX).** Accept lines now forewarn the Phase-3 dedup prompt ("…and if I spot an existing
   matching issue first I'll check with you before filing").
4. **NIT (UX).** Dropped internal phase jargon and the bare unfilled `#N` from the user-facing accept
   lines ("as I set up the branch and plan"; "closes the issue" / "one comment on it").
5. **NIT (UX).** Tightened `workflow-detail.md` Phase 1 parenthetical: the created-ticket exception is
   a Phase-3 *remote* write and no longer conflated with the local "write nothing before Phase 2"
   invariant (the Phase 2 site owns the exception).
