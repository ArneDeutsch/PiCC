# t03 — Fork hand-off (push to fork, compare URL, paste-ready PR)

## What was built
Added the fork-path hand-off half to the skill. Two new sections in `references/fork.md`
(Phase 1 fork disclosure + Phase 9 fork hand-off), routing lines in the router `SKILL.md`
(Phase 1 + Phase 9 skeletons) and `references/workflow-detail.md` (Phase 1), and a small
single-sourcing/delivery note in `references/handoff.md`.

## Key decisions
- **Single-sourcing.** `fork.md`'s Phase 9 section explicitly *replaces only* handoff.md's
  "Ticket path — open the PR and post the comment" block and reuses handoff.md's common spine
  (push/merge, CI check, ExitWorktree, final summary) and its PR-body/issue-comment **skeletons**.
  No skeleton is re-invented in fork.md. handoff.md got a short blockquote note that the skeletons
  are single-sourced and delivery differs (posted vs. paste-ready); its maintainer procedure is
  byte-for-byte unchanged (only an additive cross-reference note).
- **Compare URL** written byte-exact per the verified form: three dots, `?expand=1`, extended
  `<forkOwner>:<forkRepo>:<branch>` head. Split `target` into owner/repo; fork owner/repo from
  `push` (= fork `nameWithOwner`), `forkOwner` also via `gh api user --jq .login`. Push confirmed
  landed **before** the URL is printed (else 404).
- **Closing-keyword discipline (Left-open-adjacent, cross-repo generalization).** The linking line
  is chosen by where the resolved issue lives: issue on `target` → handoff.md's skeleton line as-is
  (`Closes #N` if fully delivered per Phase 8, else bare `#N`); issue on the fork (t05/Hole D) →
  bare cross-repo `<fork-owner>/<fork-repo>#N`, no keyword, user closes the fork issue manually;
  ticketless fork → no linking line. Never hard-coded `Closes #N`. Stray `Closes/Fixes/Resolves #M`
  from distilled text stripped regardless (Rule 3).
- **No auto-writes beyond the fork push.** Explicitly forbade any `gh pr create --head <login>:<branch>
  --repo <target>` fallback; issue comment never auto-posted.
- **Discipline write site.** Authoring the paste-ready body loads ticket-integration.md before
  distilling; falls back to the router's resident checklist floor and refuses to emit if unreadable.
- **Left open (resolved).** Optional paste-ready issue comment: chose "offer it, don't dump it by
  default" per the spec's recommendation. Final-summary wording: drafted as a UX guide, not binding
  bytes.
- **Phase 1 fork disclosure** is a genuinely new moment firing on **any** fork checkout incl.
  ticketless — placed in the scope mirror, composes with (does not replace) the ticket write-contract
  on the ticket path; is the only Phase 1 write-contract on the ticketless fork path.
- **Degrades.** Push-failure degrade mirrors handoff.md's push-rejected branch ("nothing is lost",
  actual error, nothing posted upstream, name any already-filed issue, fix + re-push, then paste-ready
  artifacts + URL template). No-gh-on-a-fork degrade falls to today's generic "push and open a PR
  yourself" with no compare URL and **never** claims an auto-PR.
- **DCO note** documented in fork.md only (not added to commit grammar): user can `-s`/`--signoff` or
  use the PR UI; skill does not auto-sign.

## Review fixes (round 2)
Applied all 7 coordinator-relayed review fixes; all landed in reference files (router untouched).

1. **MUST — compare URL form.** Switched the emitted URL from the three-part
   `<forkOwner>:<forkRepo>:<branch>` head to the **two-part** `<forkOwner>:<branch>` head (three-part +
   `?expand=1` renders "There isn't anything to compare", desktop/desktop#16269 — a dead-end). Three-part
   now mentioned only as a renamed-fork aside, not emitted by default. Dropped the `gh api user --jq
   .login` source for `forkOwner` (wrong for an org-owned fork); `forkOwner` comes from `push`'s
   `nameWithOwner` (authoritative). The forbidden-fallback example already used two-part — consistent.
2. **SHOULD (UX) — Phase 1 disclosure reframed.** Added a clause: opening the PR yourself via the web
   UI is the normal open-source contribution flow and is how you see/satisfy the upstream PR template,
   CONTRIBUTING checklist, and any CLA/DCO gate — so the manual PR reads as the feature, not a limit.
3. **SHOULD (UX) — trust hazard fixed.** fork.md step 4 now states it **replaces** handoff.md step 4's
   next-steps bullets (both the ticketless "open a PR yourself" and the ticket-path "PR is already open"
   lines) rather than "mirrors" them — a fork run has a ticket but no open PR. Also annotated handoff.md
   step 4's bullets as maintainer(non-fork)-only, pointing at fork.md for the fork variant.
4. **SHOULD (security) — credential redaction.** Push-failure degrade now strips `user:token@` from any
   remote URL in the echoed git/gh error (e.g. `https://x-access-token:TOKEN@github.com/…`), referencing
   the Phase 0 STOP-and-ask redaction rule to keep them in lockstep.
5. **NIT (UX) — DCO trigger.** Step 4 now points the user to check the upstream CONTRIBUTING / CLA / DCO
   requirements when they open the PR (dovetails with fix 2's framing and the existing DCO note below).
6. **NIT (UX) — fence-corruption guard.** Step 4 instructs that the PR body's "Start your review here"
   steps use inline `code`, never a triple-backtick fenced block (a nested fence would terminate the
   outer copyable fence).
7. **NIT (generalist) — Rule 5 clause.** ticket-integration.md Rule 5 now notes that on the fork path
   the auto-PR and auto-comment are replaced by paste-ready delivery (push is the only automatic write),
   pointing at fork.md Phase 9 — so a reader consulting Rule 5 alone on a fork run isn't misled.
