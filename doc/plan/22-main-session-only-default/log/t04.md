## What was built

  (`src/registry/compat-report.ts`), inserted in the header array right after the

## Decisions on "Left open"
- Disabled state (`subagentsEnabled === false`) is a **distinct** line rather than
  folded in, since the maxDepth wording would be misleading when all dispatch is off.
- Posture-line branches (effective value at render time):
  - `subagentsEnabled === false` →
    `Subagent nesting: subagent dispatch disabled (subagents.enabled=false); no delegation.`
  - `subagentMaxDepth >= 2` →
    `Subagent nesting: up to N level(s) below the main session (subagents.maxDepth=N).`
  - default (`=== 1`) →
    `Subagent nesting: main-session-only (subagents.maxDepth=1, PiCC default; Claude Code nests up to 5). Raise subagents.maxDepth to 2..5 in .claude/settings.json to allow nested delegation.`
- Guard error final wording:
  `Subagent nesting depth ${depth} exceeds the configured maximum (subagents.maxDepth) of ${maxDepth}. Raise subagents.maxDepth to 2..5 in .claude/settings.json to allow nested delegation.`

## Deviation / friction
- My first reword dropped the substring "exceeds the configured maximum". That broke
  a **t01-owned** test (`test/main-session-only-default.test.ts:238`, outside my
  writable surface) which asserts `toContain("exceeds the configured maximum")`.
  Rather than edit a non-writable file, I preserved that exact substring by phrasing
  it `...exceeds the configured maximum (subagents.maxDepth) of N...`. This keeps
  t01's assertion green while satisfying the t04 requirement (names `subagents.maxDepth`,
  the 2..5 remedy, still contains "depth"). No enforcement logic, settings default,
  registry notes, or prose docs were touched.
