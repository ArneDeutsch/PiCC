## Key decisions (Left-open items)

- **cell_id single-cell selection: OMITTED.** Schema is `notebook_path` only, matching the
  historical Claude `NotebookRead` minimal shape. Not load-bearing per the spec's parity
  note; t02's registry note should record the omission.
- **text/html: RENDERED** (in addition to text/plain). The rule is uniform — any `text/*`
  mime is rendered as text, any non-`text/*` mime is elided as a base64 placeholder — so
  there is no silent untested branch. Pinned with one assertion (`HTMLCONTENT_XYZ`). Did
  NOT implement the optional `data:...;base64,` collapse inside HTML (spec says "consider").
- **Header wording:** `=== Cell <index> (<type>[, id=<id>]) ===` — strong delimiter for
  unambiguous attribution; deliberately avoids `[...]` (reserved concern for the image
  placeholder / ANSI test). Index is always shown; `id=` appended only when present, so the
  no-id cell's identity is its 0-based document index (index-fallback).
- **Outputs subheader:** literal `Outputs:` line, emitted only for code cells with a
  non-empty `outputs[]`. Markdown/raw and empty-output code cells never emit it.
- **Image placeholder:** `<image/png output elided — ~<N> bytes (base64)>` where N is the
  base64 string length; uses `<...>` (never `[...]`); raw base64 never appears.
- **Text-truncation marker:** `<output truncated: showing first <n> of <m> lines>`, appended
  by the caller when `truncateHead` reports truncation (`<...>`, not `[...]`).
- **Truncation is per-text-output**, not a final whole-output truncate. This keeps every cell
  present regardless of an oversized cell's position and bounds each stream/text-plain output
  to 50KB/2000 lines. Input is separately capped by a pre-read `fs.statSync` size guard.

## Size guard / errors

- Pre-read `fs.statSync`; throw `NotebookRead: notebook too large (<N> bytes): <path>` above
  a 25 MB cap (generous — notebooks legitimately embed images — but finite so a hostile file
  can't OOM before elision runs).
- `readFileSync` + `JSON.parse` inside a broad try/catch → clean `not valid notebook JSON`.
- Structural failures throw `Error` prefixed `NotebookRead:` and **always name the resolved
  path**: not-found, not-a-file, too-large, not-valid-JSON, not-a-notebook (the last worded
  around a missing top-level `cells` array, e.g. an nbformat v3 `worksheets` file — does not
  imply corrupt JSON).
- `cells: []` returns (does not throw) `NotebookRead: notebook has 0 cells: <path>`.
- Per-cell oddities (unknown cell_type / output_type / malformed cell/output) degrade to a
  short `<...>` notice in-output; only whole-file structural failures throw.

## Joins

- `source` / `stream.text` / text-mime values → join `""` (fragments carry their own `\n`).
- `error.traceback` → join `"\n"` then ANSI-stripped (real ESC bytes removed; strip guarantees
  no `\x1b` survives).

## Review fixes (round 2)

- **FIX 1 — uniform ANSI stripping.** Moved `stripAnsi` into the shared `renderText`
  path so ALL rendered text (stream, text/plain, text/html) is stripped, not just
  `error.traceback`. Traceback keeps its own strip (it does not flow through
  `renderText`). Proved on the stream path by adding a real ESC byte to fixture cell 1
  and asserting the block contains no ESC.
- **FIX 2 — text/html base64 leak.** (a) `renderData` now prefers `text/plain` over
  `text/html` when a bundle carries both (single representation, matches Claude Code,
  avoids duplicated noise + the common base64 carrier). (b) Added `collapseDataUris`,
  applied inside `renderText` (defense-in-depth for ALL rendered text, at minimum
  covering rendered HTML): any `data:<mime>;base64,<blob>` collapses to
  `<data:<mime>;base64 … elided>`. Order in renderText: stripAnsi → collapseDataUris →
  truncateHead, so cleaning happens before size-shaping.
- **FIX 3 — truthful non-text placeholder.** Renamed `imagePlaceholder` →
  `nonTextPlaceholder`. Policy: `application/json` / `*+json` → `<mime output elided
  (structured data)>` (object value, no byte/base64 claim); string-valued raster image
  mimes (`image/*` except `image/svg+xml`, non-empty payload) keep `~<N> bytes
  (base64)`; everything else (svg XML, unknown binary, empty payloads) → generic
  `<mime output elided>`. Raw payloads still never emitted.
- **FIX 4 — traceback \n-join proof.** Added an assertion that the newline BETWEEN two
  traceback elements survives (`TRACEBACK_LINE_ONE\n  File "<stdin>", line 1`) — fails
  under a wrong `""` join.
- **FIX 5 — per-cell graceful degradation.** New `degrade.ipynb` edge-case fixture with
  an unknown output_type (`widget_view`), a null output, a null cell, and an unknown
  cell_type (`banana`). Asserts the read SUCCEEDS (details.cells === 4) and the output
  carries the `<unsupported output type: …>` / `<malformed output>` / `<malformed cell>`
  notices — proving degrade-not-throw.
- **FIX 6 — pinned image size.** Tightened the image assertion to `/~\d+ bytes \(base64\)/`.
- **FIX 7 — new fixture coverage.** rich fixture grew to 12 cells: cell 10 = text/html
  ONLY embedding a `data:image/png;base64,<blob>` (assert blob absent + placeholder
  present); cell 11 = `application/json` object (assert truthful structured-data
  placeholder, NOT base64); cell 6 repurposed to the both-html-and-plain preference case
  (assert text/plain rendered, html NOT duplicated); cell 1 stream now carries an ESC
  byte. Updated the document-order/count assertions (10 → 12 cells).
- **OPTIONAL done.** `statSync` catch now inspects `err.code`: EACCES/EPERM →
  `NotebookRead: permission denied: <path>`; otherwise `notebook not found`. Both still
  name the path and match the existing not-found test regex.
- **Judgment calls.** (1) Applied the data-URI collapse to all rendered text (not only
  HTML) since it is cheap and the spec explicitly endorsed defense-in-depth. (2) Made
  the collapse mime-group tolerant (`data:;base64,` with empty mime still collapses).
  (3) Kept the raster-image size on `joinText(value).length` guarded by non-empty so an
  array-valued image datum still reports truthfully and an object-valued one falls to
  the generic notice rather than claiming 0 bytes.
