# t03 — TaskOutput live render + streaming (execution log)

## What changed

### `src/runtime/subagent-render.ts` (taskId-gated additions to the SHARED renderer)
- New private helpers: `taskChip(details)` (the `Task(task-N)` chip, the gate for
  every background addition), `agentIdOf(details)` (isAgentId-gated `agent-<id>`),
  `pushIdentitySubline(...)` (the muted `agent-<id>` subline).
- `outcomeBadgeLine` gained an optional `taskChipLabel` → `● Task(task-3) · Agent(coder)
  completed` on completed/failed/aborted; foreground (no chip) unchanged.
- Partial branch: header leads with the chip when present; identity subline emitted;
  a `… starting…` placeholder renders when the snapshot is absent OR its tail+activity
  are empty (gated on taskId — foreground keeps its exact prior behavior via an
  `emittedBody` flag, including the no-snap contentText fallback).
- Background start block: self-identifying when taskId present (`Agent(<type>) →
  background as task-N` + muted `agent-<id> · retrieve with TaskOutput(task_id "task-N")`);
  no-taskId path keeps the original `Agent → background` header (so the FIX-B test holds).
- New running/poll branch (final render, `status==="running"`, gated on taskId): identity
  frame + one `… <lastActivity>` line, or `… starting…` when idle.
- Settled path: identity subline emitted after the badge (independent of resumable); the
  `resumable via SendMessage — agent <id>` footer stays gated on `resumable` only.
- New export `renderTaskOutputCall(args, agentType, theme)` for TaskOutput's renderCall
  (reuses the module's private clamp/theme helpers — no forked renderer).

### Double-render fix (the load-bearing one)
- Implemented in the settled body derivation, NOT inside `stripAgentTrailerForDisplay`.
  Before stripping the trailer, when `details.usage != null` (i.e. TaskOutput actually
  appended a `\nusage: …` line), the trailing usage line is removed from the DISPLAY
  source: `displaySource.replace(/\nusage:[^\n]*$/, "")`. Then the existing end-anchored
  trailer strip works, and the footer re-renders usage from `details.usage`.
  - Rationale for the gate on `details.usage`: doing the usage-strip unconditionally would
    wrongly drop a genuine body line ending in `usage:` for a task that never had one.
    Gating it avoids that false positive. The model-facing `content` is byte-identical.

### `src/runtime/background-tasks.ts` (`createTaskOutputTool`)
- Imports: `isAgentId`, `renderProgressText`, `renderAgentResult`, `renderTaskOutputCall`.
- Added `renderCall` (delegates to `renderTaskOutputCall`, looking the agent type up from
  the registry) and `renderResult` (delegates to `renderAgentResult`).
- Widened `execute` to `(toolCallId, params, signal, onUpdate)`.
- Streaming loop (only when running AND `wait !== false`): subscribe first (t02 makes
  subscribe-after-settle a no-op), emit an initial paint from `record.progress` (or a
  `… starting…` partial when undefined), then `await` — racing `registry.wait(id)` against
  a new module-level `abortSettled(signal)` helper so an aborted signal returns the
  current-status (running/poll) result with no throw; `unsub()` in a `finally`. `wait:false`
  starts no subscription.
- Content-string sanitize: `agentLabel = sanitizeLine(task.agentType ?? task.agentName ?? "",
  120) || label`, plus an `idPart` (`, agent-<id>`, gated through `isAgentId`), combined into
  a `subject` used by the running/failed/stopped content strings (completed stays verbatim).
- Details now carry `outcome` (via `noticeOutcome`, only when settled), `agent` (=
  `agentType ?? agentName ?? "subagent"`), and `cutOff` (= `task.truncated`).

## "Left open" decisions
- **renderCall WAS added** (spec left it optional): `TaskOutput(task-N) · Agent(<type>)`, agent
  type looked up from the registry — cheap and makes the poll/await legible before the result.
- **Render-test placement**: pure-renderer identity tests went in `runtime-core.test.ts` (home
  of the render `describe` + `noOverflow`/`tuiVisibleWidth`); the execute/streaming/abort tests
  went in `background-tasks.test.ts`.
- **Header layout**: single line `Task(task-N) · Agent(<type>) running…` with the `agent-<id>`
  on its OWN muted subline (so the id is never the truncated element in a crowded header). The
  width test asserts the id survives intact at widths ≥ 20 (it is 18 columns); at 1/2/3 every
  line is degenerately clamped — only `visibleWidth ≤ width` is asserted there.
- **Double-render fix location**: the usage-line drop lives in the body derivation (has access
  to `details.usage`), leaving `stripAgentTrailerForDisplay` untouched — lower-risk than
  widening the regex, and avoids stripping a legitimate trailing `usage:` body line.

## Deviations / friction
- One new test initially asserted `polled.details.agent` contained `coder`; `details.agent` is
  raw UI-only metadata (the RENDERER sanitizes it at display, matching the established foreground

  RENDERED frame is clean instead — the content string (model-facing, terminal-bound) is
  separately sanitized via `sanitizeLine` and asserted control-byte-free. No code change; the
  raw-in-details / sanitize-at-render split is the intended design.
- No changes outside the writable surface. No existing test needed editing (the no-taskId
  background path preserves the FIX-B header, and completed content stays byte-identical).

## Review follow-up (coordinator)

Addressed all four fix items + three requested tests.

- **MUST-FIX 1 (foreground regression, subagent-render.ts).** The usage-line strip
  was gated only on `details.usage != null`; since `renderAgentResult` is the SHARED
  renderer, a FOREGROUND completed dispatch (which also sets `details.usage`) whose
  final message legitimately ends in a `usage:` line would have that line deleted
  from the human view. Added `details.taskId != null` to the gate (only TaskOutput
  appends the synthetic usage line). Regression test added: a no-taskId completed
  body ending in `usage: …` is KEPT.
- **MUST-FIX 2 (subscription leak, background-tasks.ts).** (a) Moved
  `subscribeProgress` + the initial `onUpdate(partial(...))` INSIDE the `try` so a
  throwing initial paint still hits `finally { unsub() }`. (b) Replaced the
  `abortSettled(signal)` helper (which left a dangling once-listener on the
  normal-settle path) with an inline race that captures the abort listener and
  removes it via `removeAbort()` in the `finally` — so a reused session signal never
  accumulates once-listeners across TaskOutput calls. `abortSettled` deleted (unused).
- **SHOULD-FIX 3 (failed/aborted double-identity).** Added `stripTaskIdentityPrefix`
  in the renderer: for a taskId'd failed/aborted result it strips the leading
  `Background task task-N (type, agent-<id>) failed: ` / `… was aborted — ` from the
  DISPLAY body (keeping the reason / the stopped-clause). Model-facing
  `content[0].text` is unchanged (still self-identifying for print/RPC). Test added on
  the REAL execute() content of a failed AND an aborted task: body identity not
  restated, reason still shown, badge chip present.
- **SHOULD-FIX 4 (completed-resumable id shown 3×).** The settled identity subline is
  now SUPPRESSED when `resumable === true && agentId` well-formed (the footer already
  prints `— agent <id>`). Kept for non-resumable settled (its only occurrence) and
  always for live/poll. Test added: resumable → zero standalone-id lines + footer id;
  non-resumable → exactly one standalone-id subline, no invite. Consequence: the
  width test's `final` case was switched to `resumable:false` so the id-survival
  assertion still exercises a case where the id is on its own (untruncated) line — a
  resumable result intentionally puts the id only in the (truncatable) footer.
- **Tests 5/6/7.** (5) `wait:false` on an already-settled completed task →
  `outcome:"completed"` and the human render shows the badge, not the running frame.
  (6) Two concurrent `execute()` awaits on one running task → `subscriberCount===2`
  while waiting, `===0` after settle (shared-Set fan-out proof). (7) A streaming
  partial's `content[0].text === renderProgressText(snap)`.
