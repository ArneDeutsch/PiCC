# t02 — Background progress plumbing + identity-at-start (execution log)

## What changed

- **`src/runtime/subagent-progress.ts`** — added exported pure `progressActivityLine(snapshot)`
  (moved from subagents.ts), placed next to `renderProgressText`. Reads only `activity`/`tail`; no
  `pi-tui`.
- **`src/runtime/background-tasks.ts`**
  - Imports `progressActivityLine` + `type ProgressSnapshot` from subagent-progress.js.
  - `BackgroundTaskRecord` gains `progress?: ProgressSnapshot` and `agentType?: string`.
  - New private `progressListeners: Map<id, Set<listener>>`.
  - `start()` gains a 5th positional param `agentType?: string`, set on the record eagerly.
  - `record.settled` gets a shared `.finally(() => progressListeners.delete(id))` so the subscriber
    set is emptied on EVERY settle path (both `.then` handlers swallow, so `settled` always fulfills →
    one `.finally` covers fulfilled/rejected/stopped).
  - `noteProgress(id, snapshot)`: stores `progress`, derives `lastActivity` via `progressActivityLine`
    (guarded on non-empty to match old `noteActivity` semantics), fans out to subscribers (try/catch
    per listener). No-op for unknown/settled ids.
  - `subscribeProgress(id, listener): () => void`: fan-out via Set; unknown/settled → no-op returning
    no-op unsub; unsubscribe is idempotent (`active` flag).
  - `subscriberCount(id): number`: test/diagnostic accessor (deterministic leak-guard hook).
- **`src/runtime/subagents.ts`**
  - Removed the local `progressActivityLine` (now unused here — both sinks moved to `noteProgress`,
    which derives the line internally; no import added, see deviation below).
  - Both `onProgress` sinks (fresh background-dispatch branch + SendMessage-resume branch) now call
    `noteProgress(taskId, snapshot)` with the whole snapshot.
  - Both `start()` call sites pass a clean `agentType`: fresh = `label` (clean subagent type),
    resume = `record.agentName`.
  - Start message: removed the `isOneShotBuiltin` id suppression; every background start message is now
    `(agent: <type>, agent id: agent-<id>)`.
- **`test/background-tasks.test.ts`** — 3 new tests: noteProgress store/derive/fan-out/post-settle;
  agentType at start (direct + Agent-tool fresh path); leak guard across completed/rejected/stopped +
  subscribe-after-settle no-op.

## "Left open" decisions

- **`noteActivity` kept** — the existing string-only entry is still exercised by a t03 test
  (`background-tasks.test.ts` "noteActivity surfaces live activity…"), so it stays as-is (not
  wrappered over noteProgress). `noteProgress` is independent.
- **`agentType` as a `start()` parameter** (not a post-hoc field assignment) — guarantees it is present
  before any progress event and keeps both call sites single-statement.
- **Listener storage = `Set`** keyed by task id in a registry-private `Map`, with idempotent unsubscribe.

## Deviations (out-of-writable-surface test edits — flagged)

The spec's "keep test/subagent-transcripts start-message assertions green (format preserved)" is in
direct tension with the required behavior change ("stop suppressing agent-<id> for one-shot builtins…
regression against the old suppression"). One pre-existing test encoded the OLD suppression and had to
flip to stay green:

- **`test/subagent-transcripts.test.ts`** (not in writable surface): the test titled "a one-shot
  builtin (Explore) background start message omits the agent id" asserted `.not.toContain("agent id:")`
  — exactly the behavior t02 removes. Updated it to assert the id IS now present for Explore (retitled
  "NOW includes the agent id (F04 t02)"). This is the regression the spec's Testing section explicitly
  anticipates; leaving it would fail the "suite green" requirement. No other assertion in that file
  changed.
- **`test/sendmessage.test.ts`** (not in writable surface): added ONE assertion
  (`expect(record?.agentType).toBe("reviewer")`) to the existing resume-integration test — the natural
  home to cover the *resume* `start()` site's agentType (the fresh site is covered in
  background-tasks.test.ts). Non-behavioral, additive.

Both edits are the minimal necessary consequence of the specified behavior change, not scope creep.

## Notes / friction

- `progressActivityLine` is NOT imported into subagents.ts anymore: repointing both sinks to
  `noteProgress` (which derives the line) leaves subagents.ts with zero callers, so importing it would
  be an unused import. The spec's "update subagents.ts to import it from there" assumed the sinks kept
  calling it; the noteProgress repoint supersedes that. background-tasks.ts is the sole importer.
- No timers introduced. Snapshot source is unchanged (the condenser's already-sanitized snapshot).
