## Key decisions ("Left open" items)
- **Pure core `applyEdits(startBuffer, fileExists, edits, filePath)` exported** for direct testing and clarity; the tool's `execute` wraps read → `applyEdits` → write.
- **Matching is exact substring** against the current LF-normalized running buffer — no fuzzy/quote/dash/whitespace normalization. Deliberately did NOT reuse Pi's `fuzzyFindText`/`normalizeForFuzzyMatch`. `old_string` is NOT normalized, so a `\r\n` inside `old_string` won't match the LF buffer (documented Pi-matching behavior).
- **Line endings:** reimplemented private helpers `stripBom`/`detectLineEnding`/`normalizeToLF`/`restoreLineEndings` (Pi's are not on the public surface; only `generateDiffString`/`generateUnifiedPatch` are exported). On write for an existing file: `bom + restoreLineEndings(normalizeToLF(composed), ending)` — the composed buffer is re-normalized to LF once so a `\r\n` arriving via `new_string` becomes `\r\n`, never `\r\r\n`.
- **File-creation path writes the composed buffer verbatim** (no BOM, no EOL restoration) — there is no pre-existing ending to preserve. Documented inline.
- **Async `fs/promises`** (matches Pi `edit.js`), with `throwIfAborted()` checked after the read and before/after the write. No abort listener (would release the mutation queue mid-op).
- **Path resolution is plain `path.resolve(getCwd(), file_path)`** — no `resolveToCwd`/`~`/`file://`/unicode expansion (security MUST). Test 17 pins this via a literal `~` subdirectory.
- **All validation in `execute()`** (empty-edits, non-string fields, non-boolean `replace_all`) since the unit harness bypasses typebox. Also kept `minItems:1` on the schema for the model surface.
- **Concurrency:** whole read→compute→write wrapped in the exported `withFileMutationQueue(absPath, ...)`.
- Populated `details.diff`/`firstChangedLine` via the public `generateDiffString` (computed on LF-normalized content) — optional but cheap and useful; also `filePath`, `edits` count, `created` flag.
- Error messages name the file and, for multi-edit batches, `edits[i]`; single-edit calls say "the edit".

## Ordering nuance
- Per edit: empty `old_string` → creation-only branch (first edit + nonexistent file, else error); then for a non-empty `old_string` on a missing file at index 0 → file-not-found; then `old===new` → error; then count occurrences → 0 not-found / >1 not-unique (unless `replace_all`).
