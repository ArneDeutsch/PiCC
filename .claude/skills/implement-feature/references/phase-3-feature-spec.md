# Phase 3 — Feature spec

Create `doc/plan/<feature-slug>/` and write `feature.md` (template in [templates.md](templates.md)): the WHAT and WHY, explicitly **no HOW** — no file names, no interfaces, no design. Leave the `## Tasks` section as the placeholder `(filled in during task breakdown)`. If a HOW thought feels important, park it in your notes for Phase 4; putting it in feature.md anchors the design prematurely. Set the `Ticket:` line: the given/created ref, or `–` when ticketless — for a **given** fork-hosted ticket this records the **issue-host** ref (`<fork>#N`), else `<target>#N`.

**Created-ticket FILE step.** If the Phase 1 ticket-creation offer was **accepted**, this is where the issue is actually filed and the durable anchor written — together, now that the immutable slug, worktree, branch, and `feature.md` exist. Read [phase-3-ticket-file.md](phase-3-ticket-file.md) and run the FILE step now; the mechanics live there, not inline here, so a given-ticket or declined run never loads them. Load [ticket-integration.md](ticket-integration.md) first and refuse the write if it can't be read. From here the run is on the ticket path.
